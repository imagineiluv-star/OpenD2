# 검증·배포·인수 기준

## 단계별 필수 검증

| 영역 | 자동 검증 | 실제 환경 검증 |
|---|---|---|
| 파서 | 잘림·잘못된 offset/count·overflow·메모리 상한·알 수 없는 버전 | 원본 파일 해독과 프레임/지도 비교 |
| 전투 | 고정 입력·시드·경계값으로 상태 결과 비교 | 실제 조작·공격 타이밍·시각 표현 |
| 저장 | round-trip·이전 schema 변환·손상·중단 시 정상본 보존 | 재실행·업데이트 후 복원 |
| 리소스 | manifest 교차 참조·누락·중복·캐시 무효화 | 전체 캠페인·음성·시네마틱 사용 |
| 스트리밍 | 취소/늦은 완료·저장 실패·지역 상태 전이 | 반복 이동 시 끊김·메모리 회수 |
| 배포 | 플랫폼 export·패키지 의존성·해시 | 깨끗한 OS에서 설치·실행·제거 |
| 협동 | 버전 불일치·잘못된 명령·재접속·버퍼 경계 | 두 장비의 지연·손실·호스트 종료 |

게임 원본이 필요한 시험은 로컬 opt-in으로 분리한다. 공개 CI에 게임 데이터·상용 리소스·개인 세이브를 업로드하지 않는다. 합성 fixture는 실제 규격의 경계 조건을 검증해야 하며 구현의 반환값을 그대로 정답으로 복사하지 않는다.

## 잠정 성능 예산

아래 수치는 측정 결과나 보장 사양이 아닌 초기 개발 목표이다. M3에서 장비 모델·CPU/GPU·RAM·OS·드라이버·해상도·품질 프리셋·빌드 커밋을 고정해 재조정한다.

| 지표 | 초기 목표 | 측정 방법 |
|---|---|---|
| 렌더링 | 대표 장면 1080p, 프레임 시간 p95 ≤16.7ms | 워밍업 후 10분, CPU/GPU 시간 별도 기록 |
| 시뮬레이션 | 잠정 25Hz, tick p99 ≤10ms | 적·투사체·아이템 수를 고정하고 기록 |
| 지역 전환 | 이동 중 메인 스레드 동기 디코딩 제거 | 경계 이동 프레임 최대값·p99와 로딩 단계 기록 |
| 메모리 | 동일 경로 20회 이동 후 지속 증가 없음 | 관리 heap·네이티브 메모리·VRAM 분리 추적 |
| 안정성 | 대표 전투·이동 2시간, 비정상 종료·저장 손상 0 | 로그·메모리·프레임 시계열 보존 |

총 RAM/VRAM 상한과 첫 실행 시간은 자산 실측 후 정한다. 빈 장면의 fps로 최종 성능을 주장하지 않는다. 개발 환경과 릴리스 빌드를 구분하고, 네이티브 리소스 누수는 관리 heap만으로 판정하지 않는다.

대표 장면은 마을 하나, 던전 하나, 플레이어 하나로 시작한다. 몬스터 10/50/100, 투사체·스킬 이펙트 동시 발생 등 부하 단계를 구분한다. 단계별 결과는 실측 자료로 남기고 통과한 구간만 지원 범위로 표시한다.

## 설치와 업데이트

1. Windows x64와 macOS arm64를 우선 배포 대상으로 한다. Linux x64는 개발/서버 및 후속 클라이언트 검증 대상으로 둔다.
2. 사용자 패키지는 Godot 에디터, .NET SDK, DB 서버 설치를 요구하지 않는다. 내보내기 결과의 런타임 포함 여부와 네이티브 의존성을 실제로 검사한다.
3. 첫 실행에서 원본 데이터 경로를 지정한다. 누락·버전 불일치에는 해결 가능한 안내를 제공한다.
4. 저장·설정·캐시는 OS 사용자 데이터 경로에 둔다. 업데이트가 세이브를 삭제하지 않아야 한다.
5. 초기 배포는 버전별 완전 패키지 교체로 단순화한다. 자동 업데이트는 이후 추가하되 패키지 서명/해시, 실패 복구, 이전 버전 복귀를 검증한다.
6. Windows 코드 서명, macOS 서명·공증은 배포 단계 작업으로 추적한다. 인증서·계정 비용과 준비 전에는 경고 없는 설치를 보장하지 않는다.

## 리저렉션 수준 목표의 인수

기술 인수와 아트 인수를 분리한다. 기술 인수는 기능 호환·프레임·메모리·저장 안정성이고, 아트 인수는 캐릭터 실루엣·재질·애니메이션·조명·전투 가독성·UI 일관성이다. 비교 장면과 해상도·카메라·조명을 고정해 이미지/영상으로 평가한다.

대표 장면 성공은 전체 게임 품질 완료가 아니다. 전체 콘텐츠 제작량과 리소스 지원율을 별도로 보고한다. 구현되지 않은 콘텐츠를 제거하여 호환율을 높이지 않는다.
