# PLAY-08 — 원본 지형 장면 설정 간소화

기준: `d174946` (M2-06d), 작업 브랜치 `feat/play-08-scene-setup`.

## 변경 이유와 범위

첫 원본 지형 플레이에도 scene JSON을 수동 작성하고, 시작 메뉴에서 새 게임을 먼저 열어야 했다.
Map의 실제 경로/팔레트 미리보기를 재사용해 명시적 셀 배치로 한 지역 장면을 만들고 시작 메뉴에 연결한다.

- 데이터 폴더 검사: 찾은 아카이브 수와 누락 파일명. 버전/내용 호환 판정과 분리.
- 지도 → 제목/Player/Monster/Guide 셀 좌표 → 검증 → 사용자 `scenes/`에 고유 이름의 JSON 생성.
- 좌표 범위/중복/충돌/퀘스트 왕복 연결 및 기존 로더의 입력·픽셀·셀 예산 검사.
- 검증한 요청 스냅샷만 직렬화. 임시 파일 flush 후 새 파일로 이동하며 기존 파일을 덮어쓰지 않는다.
- 지도 입력 수정/테이블 경로 변경 시 이전 지도 생성 자격 해제. 로딩 중 변경된 입력은 완료 후에도 자격을 얻지 않는다.
- 데이터 폴더가 달라지면 지도 재로드 요구. 생성 중 버튼 재진입 차단.
- 시작 메뉴에서 원본 JSON/최근 장면 로드. 성공 후 메뉴에서 정지 상태를 유지하고 Continue로 시작.
- 현재 세션 교체는 확인하며 취소/실패 시 세션과 기존 파일/최근 경로 유지. 성공한 scene의 별도 체크포인트 슬롯 사용.

생성 결과는 원본 지형과 **임시 actor 표시**, 한 지역·플레이어 1명·몬스터 1마리·Guide 1명·처치 퀘스트다.
아트·오디오·포털·원작 UI·원본 오브젝트 의미·캠페인을 자동 생성하지 않는다.
원본 폴더에는 쓰지 않으며 원본 리소스를 복사하거나 배포본에 포함하지 않는다.

## 검증

- 실행형 계약 **275/275**: 기존 268개 + 신규 7개.
- 새 계약: 합성 MPQ → 설치 로더 → 생성 JSON → 실제 scene 로더 왕복, 소스 바이트 보존;
  셀 좌표 변환/플레이 세션 생성; 입력 경계; 범위·연결 실패 전 파일 미생성;
  기존 파일 보존/임시 파일 정리; reader가 호출자 입력을 바꿔도 검증한 스냅샷 유지; 리소스 누락 시 미생성.
- Python 패키징/다운로드 계약 **16/16**.
- Godot 통합: 시작 합성 지도에서 생성 금지, 작업 중 재진입 금지, 경로 수정 후 상태 무효화.
  생성한 합성 scene을 실제 메뉴 로드 경로로 읽고 정지/이어하기/저장 슬롯을 검증한다.
  실패/취소 시 state hash와 최근 경로 보존도 검사한다.
- `OPEND2_PLAY08_SETUP_READY`를 개발용 및 추출 배포본 smoke의 필수 marker로 추가.
- 최종 Linux 검증 성공: locked restore, 전체 build(경고/오류 0), 경계 검사·기존 상태 벡터, Godot import/headless, self-contained export 및 SDK 경로를 제거한 배포본 headless smoke. 원격 3개 OS 검증은 PR의 CI 결과를 따른다.

첫 smoke에서 LineEdit의 프로그램적 Text 변경은 사용자 TextChanged 신호를 발생시키지 않는 것을 확인했다.
테이블 경로 지정 시 명시적으로 기존 지도 상태를 무효화하고, 사용자 편집 검증은 해당 신호를 발생시켜 수정했다.
새 합성 MPQ 계약의 초기 fixture 경로도 MPQ 표준 구분자로 정규화했다. 오류를 숨기거나 테스트를 생략하지 않았다.
