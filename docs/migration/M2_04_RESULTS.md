# M2-04 드롭·인벤토리·장비 검증

검증일: 2026-10-08 UTC. 저장소 `imagineiluv-star/OpenD2`, 브랜치 `feat/m2-playable-slice`, 기준 master `5093753b1ac301431c6ea0593d3684c7c8e40e0f`.

## 실제 구현

몬스터 처치에서 드롭·습득·장비 변경·전투 능력치까지 이어지는 최소 흐름을 구현했다. `GameItems`가 소유권과 이동을 판정하고, Godot 화면은 명령을 제출하고 결과를 표시한다. 서버 프로세스나 외부 패키지는 추가하지 않았다. 기존 원본 리소스 로더와 C++ 파일을 유지한다.

- 몬스터의 생존→사망 전환마다 아이템 하나를 생성한다. 짝수 몬스터 ID는 검, 홀수 ID는 갑옷인 **합성 드롭 규칙**이다. 전투 난수를 소비하지 않으며 원본 드롭 확률을 구현한 것이 아니다.
- 아이템은 별도의 `ItemId` 이름 공간에서 사망한 몬스터 ID를 사용한다. 최대 아이템 수는 초기 몬스터 수로 제한된다. 시체/지역 재방문으로 다시 생성하지 않는다. 처음부터 죽은 객체에는 아이템을 생성하지 않는다.
- 아이템 상태는 바닥·가방·장착 중 하나다. 바닥에는 지역·위치가 있고, 소유 아이템에는 소유자·슬롯이 있다. 가방은 8칸, 장비는 무기·몸통 두 슬롯이다. 이번 단계에는 중첩 수량이나 직사각형 아이템 배치가 없다.
- 습득 시 생존·행동 가능 여부, 바닥 상태, 같은 지역, 거리 384 이내, 충돌 시야, 빈 가방칸을 검사한다. 같은 tick의 중복 입력도 실행 시 다시 검사한다.
- 장비 교체는 기존 장비를 들어오는 아이템의 가방칸으로 옮긴다. 가방이 가득 차도 교체가 가능하다. 해제는 빈칸이 없으면 실패하며 아이템 이동은 발생하지 않는다. 버리기는 가방 아이템에만 허용하며 현재 위치에 같은 ID로 놓는다.
- 기본 피해 14~20, 검 장착 시 +6. 갑옷은 피격 피해를 2 줄이며 최종 피해는 최소 1이다. HP/최대 HP는 장비로 변경하지 않는다. 실제 전투 계산이 장비 상태를 사용한다.
- 명령은 tick·actor·sequence 순서로 아이템 이동을 처리한 뒤 AI/공격/이동을 수행한다. 따라서 그 tick에 장착한 장비는 같은 tick의 전투에 반영된다. tick 시작 시 피격 정지 상태면 아이템 행동이 실패한다. 사망한 플레이어의 예약 명령은 실행하지 않는다.
- 지역 전환은 장비·가방 소유권을 유지하고 바닥 아이템은 해당 지역에 남긴다. 기존 포털의 예약 입력 취소 규칙은 아이템 입력에도 적용된다.

## 클라이언트 조작

Simulation 탭에서 몬스터를 처치한 후 청록색 아이템 표식에 접근해 **F / Pick up nearest**를 누른다. 선택 목록에서 아이템을 고르고 **Equip selected / Unequip selected / Drop selected**로 조작한다. 가방 사용량과 피해 범위·방어력이 표시된다. F는 누르는 순간 한 번 처리한다. **Verify replay**에 아이템 명령과 상태도 포함된다.

현재 인터페이스는 합성 검사용이다. 고품질 HUD, 원본 아이콘·3D 장비 표현, 게임패드·GUI 인수는 후속 작업이다. **New run**과 앱 종료 시 상태를 잃으며 파일 저장은 M2-05다.

## 상태 경계와 예산

`RulesVersion = 4`. 명령에 `ItemId`를 추가하고 상태 해시에 아이템 개수·생성 순서의 ID·종류·위치 유형·소유자·슬롯·지역·좌표를 포함한다. 고정 합성 카탈로그의 변경도 규칙 버전 변경 대상이다. 스냅샷은 아이템 배열을 복사하여 읽기 전용으로 제공한다. v3 재생/파일을 자동 변환하는 API는 없다.

아이템 배열은 생성 시 전체 객체 수만큼 미리 할당하며 tick에서 늘리지 않는다. 이벤트 상한은 `7 × 전체 객체 수 + 128 + (월드 사용 시 4)`다. 가방·장비 조회는 유한 아이템 배열을 순회하므로 대형 월드에서는 소유자/지역별 인덱스가 필요하다. 이번 결과는 대형 월드의 성능 보장이 아니다.

## 검증

- 전체 솔루션 빌드: 경고 0, 오류 0. Debug 계약 **164/164 통과**(기존 147 + 아이템 17).
- 중복 드롭/습득, 잘못된 ID/입력·소유자, 가방 초과, 가득 찬 가방의 교체/해제, 두 장비 슬롯, 반복 장착, 버리기/재습득, 거리/벽/타 지역, 피격 정지/사망, 지역 왕복, 스냅샷 소유권, 입력 재생을 검사한다.
- 같은 전투 난수 흐름에서 검의 실제 추가 피해 +6, 갑옷의 실제 피해 감소 2를 대조했다.
- 준비된 100회의 장착/해제 tick에서 관리 메모리 할당 0바이트를 확인했다. 기존 다지역/전투 무할당 계약도 통과했다. UI·진단·명령 제출까지 무할당이라는 뜻은 아니다.
- `eng/check-state-vectors.py`의 독립 Python little-endian 인코딩과 C# 이동·전투·퀘스트의 세 고정 hash가 일치한다. 전체 검증과 CI에서 이 스크립트를 실행한다.
- Godot import·헤드리스 시작·Linux self-contained export 성공. SDK 환경변수와 개발 도구 PATH를 제거한 배포 실행도 종료 코드 0으로 모든 준비 마커를 출력했다.
- 원격 기능 브랜치와 PR의 Linux/Windows/macOS CI가 모두 성공했다. 각 OS에서 164개 계약·Godot 시작·self-contained export를 검증했다.

실행 명령:

```sh
python eng/validate.py --export Linux
env -u DOTNET_ROOT -u DOTNET_ROOT_X64 PATH=/usr/bin:/bin \
  ./artifacts/Linux/OpenD2.x86_64 --headless --quit-after 120 -- --smoke-test
python eng/verify.py
git diff --check
```

`OPEND2_M204_ITEMS_READY`는 처치 → 습득 → 장착 → 능력치와 재생 일치를 검사한다. 헤드리스 검증은 실제 사용자 PC의 조작·설치·서명/공증 인수를 대체하지 않는다.
