# 원본 MPQ 등록과 후속 이관

원본 MPQ는 아직 제공되지 않았다. 아래 도구는 사용자 파일의 **복사와 무결성 등록**이며
MPQ 디코딩, 원작 호환, 실제 화면 검증 결과가 아니다. 원본을 다운로드하거나 업로드하지 않는다.

## 로컬 등록

Python 3.12 이상에서, Git 작업 폴더 밖의 개인용 보관 경로를 지정한다.
입력은 ZIP이 아닌, 사용자가 압축을 해제한 MPQ 디렉터리다.

```sh
python eng/original_data.py register --source "/path/to/Diablo II" --vault "/path/to/private-vault" --version "1.10f" --language "ko"
python eng/original_data.py verify "/path/to/private-vault/<출력된 dataset ID>"
```

모르는 버전/언어는 옵션을 생략한다. 명시한 값도 신고값이며 검증된 버전이 아니다.
MPQ만 복사하고 세이브·키·다른 파일은 포함하지 않는다. 원본을 변경하지 않는다.
파일명·바이트 크기·SHA-256과 신고값으로 데이터 세트를 구분하며 절대 원본 경로는 기록하지 않는다.
같은 세트 재등록은 검증 후 재사용한다. 변경된 원본/신고값은 새 세트가 되고, 손상된 기존 세트는
덮어쓰지 않고 오류를 낸다. 임시 복사본을 검증한 후 최종 디렉터리로 옮긴다.

결과는 `<dataset ID>/mpq/`와 `manifest.json`이다. 이 mpq 폴더를 기존 클라이언트의 데이터 경로로
선택할 수 있으나, 실제 지원 여부와 장면 JSON 구성은 별도로 확인해야 한다.
원본의 의도치 않은 변경을 찾는 해시이며 진품 인증이나 서명은 아니다.
기본 한도는 256개·파일당 8 GiB·합계 32 GiB다. 디스크 여유 공간도 필요하다.
동시에 원본을 패치하거나 여러 등록 프로세스로 같은 보관함을 쓰지 않는다.

Git checkout 안의 출력, 경로가 겹치는 입력/출력, 심볼릭 링크, 모호한 파일명 및 손상을 거부한다.
등록 성공이어도 `compatibility_status`와 `gui_status`는 `NOT_RUN`이다.
CI는 가짜 바이트로 등록/손상/경로 경계만 시험하고 실제 원본 데이터를 포함하지 않는다.

## 다음 이관 순서

1. 실제 MPQ 수신과 등록 → 원본 버전/언어/패치 우선순위 확인.
2. 현재 `LegacyPlayScene` 로더로 대표 지형·캐릭터·NPC·HUD 장면을 구성하고 화면 비교.
3. 실제 장면 의존 경로와 선택된 원본 해시를 수집해 개인용 장면 팩 작성.
4. `LegacyPlayScene.Load(request, read)`에 팩 읽기 공급자를 연결하고 MPQ 없이 같은 장면인지 검사.
5. 필요할 때 팔레트·방향·피벗·타이밍·충돌·레이어를 보존하는 변환 캐시 도입.

현재 패치 검색 순서는 `GameInstall.Priority`가 담당한다. 팩 작성 시 동일한 선택 결과를 유지하고,
원본이 손상되면 하위 버전으로 조용히 우회하지 않는다. 캐시 키에는 원본 해시·변환기 버전·옵션이 필요하다.
파일만 이동했을 때 장면 ContentId와 체크포인트가 유지되는지 검사한다. 실제 콘텐츠 변경은 별도 세트다.

공개 GitHub에는 코드와 합성 검사를 관리하고, 원본과 원본 포함 패키지는 별도 개인용 보관 영역에 둔다.
이 도구가 보관 경로의 접근 권한/클라우드 동기화 설정을 변경하거나 비공개 저장소를 만드는 것은 아니다.
팩 작성기·팩 로더·자동 장면 진입·실제 GUI 인수는 아직 구현/완료되지 않았다.
