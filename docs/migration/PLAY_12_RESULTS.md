# PLAY-12 — 인벤토리 아이템 아트 연결

기준 master: `03ea6db` (PLAY-11). 작업 브랜치: `feat/play-12-item-artwork`.

## 목적과 구현

기존 가방/장비 슬롯에 사용자 소유 원본 DC6 아이콘을 표시한다. 현재 preview 아이템인
TrainingSword / TrainingVest에 이미지를 명시적으로 연결하며 원본 아이템 수치·규칙을 가져오지는 않는다.

- 선택 `ItemArtwork`: 팔레트와 Definition/Path/Frame 목록. 정확한 catalog 이름만 허용하며 중복은 거부한다.
  일부 아이템만 지정할 수 있다. 누락된 아이콘은 기존 이름·툴팁으로 표시한다.
- 경로/팔레트/프레임을 추측하지 않는다. 같은 정규화 경로·프레임은 읽기/디코딩/텍스처를 공유한다.
  opacity와 불투명 palette index 0을 보존한다. DC6 offset은 슬롯 위치에 더하지 않는다.
- 파일당 32MiB, 아이템 입력 64MiB, 아이콘 크기 1..256×1..256. 큰 프레임은 픽셀 배열 생성 전에 거부한다.
  scene의 입력 128MiB·디코딩 픽셀 16,777,216 한도에도 합산한다.
- 입력 배열은 I/O 전에 복사한다. 설정·소스 SHA-256이 ContentId와 장면 체크포인트 슬롯에 반영된다.
  ItemArtwork가 없는 기존 장면의 identity와 Core 규칙/저장 형식/상태 벡터는 유지된다.
  새 앱은 기존 장면을 읽으며 새 필드를 포함한 JSON은 구버전 앱에서 거부된다.
- Scene art → Item artwork settings: 전체 사용 여부, 아이템별 사용 여부/경로/프레임,
  팔레트, 슬롯 크기 미리보기, 새 복사본 검증/저장/재열기/비활성화.
  저장 중 편집 금지·데이터 폴더 변경 검사·실패 시 이전 미리보기/파일 유지.
- 가방·무기·방어구 버튼에 비율 유지/nearest 아이콘을 표시한다. 장착/해제/버리기/줍기 후 슬롯을 갱신한다.
  이름·툴팁·기존 입력과 8칸 preview 가방은 유지한다. 장면 전환/종료 때 참조를 끊고 텍스처를 해제한다.
- 아이템/HUD 텍스처와 지형을 준비한 뒤 적용한다. 잘못된 새 장면 로드는 이전 세션/아이콘/메뉴 상태를 보존한다.
- CLI `ItemArtworkSources`, 준비 보고서 `ItemArtworkCount` 추가. 기존 readiness/종료 코드 의미는 유지한다.
  지정 개수는 원본 GUI/규칙 검증 완료를 의미하지 않는다.

## 검증

로컬 최종 검증 결과와 원격 PR CI를 구분해 기록한다.

- 신규 계약 8개: 정규화/공유/alpha, I/O 이전 정의 검증, 방향별 frame 선택/크기 제한,
  입력 한도, source/설정 identity·snapshot 소유권, 이전 scene/Core 상태 호환,
  새 파일 저장 왕복/실패 보존, scene 합산 입력 한도.
- Godot 합성 smoke: RGBA 업로드, 가방→장비→가방→드롭→줍기 아이콘,
  매핑 없는 방어구의 이름 표시, 빈 슬롯/장면 해제 시 아이콘 제거.
  설정 미리보기/실패 보존/저장/재열기/비활성화·잘못된 scene 로드 시 세션 보존.
- 개발용·배포본 필수 marker: `OPEND2_PLAY12_ITEMS_READY`, `OPEND2_PLAY12_ITEM_SETUP_READY`.
- 실행형 계약 **305/305** (기존 297 + 신규 8), Python 패키징/다운로드 계약 **16/16** 통과.
- pinned .NET/Godot·native backend 준비 후 Linux locked restore/build(경고·오류 0), 경계/기존 상태 벡터,
  Godot import/headless·self-contained export·SDK 경로를 제거한 배포 실행 검사 통과.
- 압축 해제 패키지와 원격 Windows/macOS/Linux 결과는 PR CI에 기록한다.

초기 컴파일의 중복 종료 훅을 기존 종료 처리에 합쳤다. 환경 복구 중 native NPC 빌드가 끝나기 전에
수행한 전체 계약/실행 검사에서는 런타임 누락이 검출됐다. pinned 빌드 완료 후 전체 검증을 다시 통과했으며
검사를 건너뛰거나 실패 판정을 완화하지 않았다.
