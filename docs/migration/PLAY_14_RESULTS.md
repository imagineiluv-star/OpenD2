# PLAY-14 — 격자 인벤토리와 이전 저장 변환

기준 master: `c58e235` (PLAY-13). 작업 브랜치: `feat/play-14-grid-inventory`.

## 목적과 구현

기존 8개 슬롯은 아이템 크기를 표현하지 못했다. 이번 단계는 크기·좌표·점유와 이동을 Core에 추가하고
기존 파일을 검증해 새 저장으로 변환한다. 전체 원본 아이템 규칙·원작 UI 재현을 완료한 것은 아니다.

- `InventoryLayout`: 엔진 독립 immutable 코드/크기 정의, 10×4 격자. 기본 검 1×3·방어구 2×3.
  현재 두 preview 정의를 유지한다. Slot은 가방에서는 `y*10+x`인 왼쪽 위, 장비에서는 기존 enum 값이다.
  40bit mask로 행 끝/아래쪽 넘침과 겹침을 검증하며 회전·정렬·스택 분할은 지원하지 않는다.
- 줍기/일반 해제는 행 우선 first-fit. MoveItem은 지정 위치 이동 또는 한 아이템과 교환한다.
  되돌아갈 위치까지 둘 다 검증한 뒤 갱신한다. 둘 이상과 겹침·역방향 크기 불일치·공간 부족은 원래 상태를 보존한다.
  장비에서 가방의 지정 빈 공간으로 이동할 수 있다. 장비 해제와 가방 교환을 묶은 동작은 지원하지 않는다.
- 명령 payload/소유자/기절/사망/지역과 tick 시점의 점유를 재검사한다. tick 내부 새 할당과 파일 I/O는 없다.
  RNG를 소비하지 않으며 크기/코드 콘텐츠 hash가 상태 hash·snapshot·replay에 포함된다.
- `UseItemDimensions`는 scene schema 1의 선택 bool(default false). true면 연결한 TXT 코드/크기를 Core에 복사하고
  scene identity에도 반영한다. 바인딩 누락·10×4 밖 크기는 거부한다. false면 기존 scene identity를 유지한다.
  피해·방어·장착 요구치·스택·옵션은 아직 preview 규칙이다. Code는 고정 정의 연결이며 전체 아이템 인스턴스 이관이 아니다.
- 가방 버튼을 실제 점유 사각형으로 배치하고 포함된 칸의 중복 버튼은 숨긴다. 아이콘·이름·상세·점유 칸 수를 표시한다.
  드래그/드롭, 아이템→Move selected→목적 칸(Tab/Enter), 칸 버튼 Escape 취소, 장비 칸 드롭을 연결한다.
  drag payload의 세션 번호와 현재 소유권을 검사해 새 게임/로드 이전 입력을 거부한다. 메뉴/확인/파일 작업 중 입력을 막는다.
- CLI scene 보고서에는 실제 InventoryLayout/ContentHash가 포함된다. 준비 보고서의 원본 규칙/GUI 판정은 그대로 미검증이다.

## 저장 호환 정책

새 파일은 **schema 2 / rules 5**이며 아이템 코드/크기를 함께 저장한다. 다른 크기·코드/월드의 파일은
호환 오류로 보존한다. 구버전 앱은 새 파일을 읽을 수 없다.

이전 **schema 1 / rules 4**만 자동 변환 대상으로 명시한다.

1. 이전 콘텐츠 identity, 8개 슬롯 상태·소유권·아이템·예약 명령과 **기존 v4 hash**를 먼저 검증한다.
2. 플레이어별 기존 가방 슬롯 순서로 새 크기를 first-fit 배치한다. 장비·바닥 항목·ID·tick·RNG·명령 큐를 유지한다.
3. 로드는 메모리만 변환한다. 다음 명시적 저장에서 기존 정상 파일을 `.bak`으로 남기고 원자 교체한다. 백업은 기존의 1세대 회전 정책을 따른다.
4. 배치가 안 되면 호환 오류를 반환한다. 아이템을 버리거나 오래된 백업을 대신 열지 않는다.
   이전 앱에서 가방을 줄이고 저장한 뒤 다시 시도할 수 있다. first-fit은 전역 최적 패킹을 보장하지 않는다.
5. 손상 주 파일은 기존 정책대로 정상 백업을 검사한다. 백업도 옛 형식이면 동일 검증/변환을 거친다.

이전 전체 replay 엔진을 유지하는 것은 아니다. 검증된 checkpoint 이후부터 새 규칙을 사용한다.
원본 `.d2s` 아이템 본문 변환과 구별한다. 크기 옵션을 켠 scene은 다른 checkpoint 슬롯을 사용한다.

## 검증

- 실행형 계약 **334/334** (317 + 신규 17), Python **16/16**.
- 크기/코드 snapshot 소유권·identity, 40bit 경계/단편화, 자기 영역 이동·다른 크기 교환·다중 겹침 거부,
  권한·기절/사망·같은 tick 재검사, restore 겹침 거부, queued move 저장/재생, 실제 TXT 필드의 선택 크기 적용.
- 이전 master의 **수정하지 않은 Core**가 생성한 합성 v1 파일 두 개를 고정 fixture로 보존했다.
  정상 변환/예약 명령·체크섬 손상·8칸 범위 위반·공간 부족·파일/백업 보존과 새 저장 재로드를 검사한다.
- 독립 Python little-endian 상태 벡터를 rules 5와 layout hash에 맞게 갱신하고 C# 고정 예상값과 대조했다.
  fixture의 기존 v4 hash는 그대로 유지했다. 테스트 기대값을 실행 결과만 복사해 정하지 않았다.
- Godot headless: 사각형/포함 칸·셀 수, 드롭 callback→명령→tick→UI, 교환/거부, 키보드 버튼 활성화,
  장비로/장비에서 이동, Escape/메뉴/이전 세션 차단, scene 크기 옵션 저장/재열기/실패 보존.
  필수 marker: `OPEND2_PLAY14_GRID_READY`, `OPEND2_PLAY14_GRID_SETUP_READY`.
- Linux locked restore/build 경고·오류 0, 경계 검사·전체 계약, Godot import/headless,
  self-contained export와 SDK 검색 경로를 제거한 배포본 smoke 통과.
- 압축 패키지 및 Windows/macOS/Linux PR CI 결과는 PR에 구분해서 기록한다.

초기 UI 문자열 개행 컴파일 오류를 수정했다. 다중 겹침 테스트는 최초 fixture가 실제로 유효한 단일 교환을
가리키는 것을 확인해 두 점유 항목과 겹치는 배치로 바로잡았다. 거부 규칙이나 검증 기준을 완화하지 않았다.
