# M5-01d-1 — 캐릭터별 공유 퀘스트 완료 기록

공동 월드의 공유 퀘스트는 방이 닫히면 사라졌다. 이 단계는 **어느 캐릭터가 그 퀘스트를 끝냈는지**를
서버 저장소의 캐릭터에 남긴다. 직업·레벨·경험치는 Core에 개념이 없으므로 이 단계의 범위가 아니다.

## 규칙

| 항목 | 계약 |
| --- | --- |
| 크레딧 시점 | 공유 퀘스트가 `Completed`가 되는 tick. Core가 낸 `QuestChanged(Completed)` 이벤트로 판단한다 |
| 크레딧 대상 | 그 tick이 끝났을 때 **살아 있는** 참가자. Core의 완료 보상(체력 회복) 대상과 같은 기준이다 |
| 사망자 | 부활이 없으므로 이후에도 대상이 되지 않는다. 같은 tick에 보상 직후 사망한 참가자도 제외된다(tick 종료 시점 판정) |
| 저장 | `Member.QuestCredit`으로 방 저장(`SavedGame`)과 같은 파일·같은 `Save()`에 기록한다. 완료와 크레딧은 항상 함께 복원된다 |
| 확정 | 방장이 방을 닫을 때 크레딧을 가진 참가자의 `Character.Quests`에 월드 ID별 `Completions`를 1 늘린다 |
| 승리 횟수 | 기존 규칙(완료 시 모든 참가자 +1)을 바꾸지 않는다 |
| Arena | 월드가 없으므로 기록·크레딧 모두 없다 |

기록 키는 월드 **콘텐츠 ID**(`cooperative-demo-v1`)이며 해시가 아니다. 콘텐츠가 바뀌면 ID가 바뀐다는
기존 규약을 따른다.

## 와이어와 저장 형식

- `CharacterInfo.Quests`(`{ World, Completions }[]`)는 기록이 있을 때만 직렬화한다. 기록이 없는 캐릭터의
  JSON은 이전과 바이트 단위로 같다.
- `realm.json`의 DB 버전은 올리지 않는다. `Member.QuestCredit`과 `Character.Quests`는 선택 필드이며
  없는 구형 파일은 `false`/없음으로 읽는다.
- 로드 시 검증: 기록 최대 8개, 월드 ID `[a-z0-9-]{1,64}`, 중복 금지, `Completions` 1..1,000,000.
  크레딧은 **완료된 월드 퀘스트가 있는 방**에서만 허용한다. 위반하면 `InvalidDataException`이며
  파일을 덮어쓰지 않는다. 월드 ID가 이 빌드의 콘텐츠인지는 검사하지 않는다(다른 빌드의 기록 보존).
- 완료 횟수는 상한에서 포화한다. 방 종료 도중 예외로 일부 캐릭터만 갱신되는 일이 없게 한다.

## 검증

`PersonalQuestContracts`(Realm/Open 각각, 실제 `Realm` 서버 객체):

1. 서버가 만든 4인 월드 방(실제 로그인·참가·시작)을 체크포인트한 뒤, 저장된 게임만 "몬스터 사망·턴인 대기·
   1·2번 참가자는 NPC 곁, 3번은 사망" 상태로 교체한다(상태 해시는 Core가 계산).
2. 1·2번이 실제 `Interact` 입력을 보내고 `Tick()` → 퀘스트 `Completed`.
3. 방을 닫기 전에 서버를 재시작해 크레딧 유실이 없는지 확인한 뒤 닫는다.
4. 1·2번만 `Quests == [(cooperative-demo-v1, n)]`, 3번은 없음·JSON에 `Quests` 필드 없음, 승리 횟수는 전원 n.
5. 같은 과정을 한 번 더 반복해 `Completions == 2`, 재시작 후에도 유지.
6. 거부 후 파일 보존: 미완료 퀘스트의 크레딧, 0/음수/초과 횟수, 잘못된 월드 ID, 중복 월드, 기록 개수 초과.
7. 구형 DB(`Quests`/`QuestCredit` 없음) 로드.

변이 확인: 사망자를 크레딧에서 빼는 조건을 없애면 4번 검사가, 종료 시 기록을 쓰지 않으면 1번 검사가 실패한다.

## 하지 않은 것 / 남은 항목

- **개인별 수락·진행**: 지금 퀘스트 상태는 방 전체가 공유하는 Core 상태 하나다. 개인 상태는 Core 규칙·상태
  해시(그리고 `cooperative-demo-v1` 콘텐츠 해시) 변경이 필요해 별도 단계로 둔다.
- **Open 캐릭터 파일**: 이 단계에서는 형식 2가 완료 기록을 담지 않아 내보내기/가져오기를 거치면 기록이 끊겼다.
  M5-01d-2에서 형식 3과 `characterFileVersion: 3` 협상으로 해결했다([ONLINE_MODES](ONLINE_MODES.md#open-캐릭터-파일-이관-이름승리-횟수소유-아이템퀘스트-완료-기록)).
- **Godot 표시**: 클라이언트는 `Quests`를 아직 읽거나 보여 주지 않는다(알 수 없는 필드는 무시).
- **직업·레벨·스킬**: Core에 개념이 없다. 새 게임 규칙이므로 이 문서의 범위가 아니다.
- **이전 빌드에서 이미 완료된 채 열려 있는 방**: 크레딧 플래그가 없으므로 닫아도 기록이 남지 않는다
  (승리 횟수는 기존대로 오른다). 사망 여부를 사후에 알 수 없어 소급 부여하지 않는다.
- 실제 MPQ 콘텐츠·두 PC 환경은 검증하지 않았다. 모든 검증은 내장 합성 월드 기준이다.
