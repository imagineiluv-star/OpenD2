# NPC-02a — 선택형 로컬 추론과 모델 설치

갱신일: 2026-10-08 UTC. **로컬 추론·선택 설치·한국어 CPU 의도 비교를 구현했다. NPC-02 전체 인수는 미완료다.** 의도 품질 개선, 실제 사용자 PC의 RAM/VRAM·GPU·렌더링 병행, 일반 사용자 설치·서명 인수는 NPC-02b로 남긴다. NPC 기억·자유 대사·자율 행동을 구현한 것으로 보지 않는다.

## 동작과 설치

- 기본 게임은 모델 없이 즉시 실행한다. 앱을 다시 열면 기본 대사를 사용하며 자동 다운로드/자동 모델 실행이 없다.
- Simulation의 Camp Guide 아래에서 모델/용량을 보고 Download model → Start local AI를 선택한다. Cancel/이어받기, Use basic dialogue, Remove model을 제공한다. 부분 다운로드도 제거할 수 있다.
- 다운로드한 GGUF는 사용자 `npc-models/`에 둔다. 경로/출처/불변 revision/크기/SHA-256을 코드에 고정한다. 검증한 임시 파일만 원자적으로 교체하고 실행할 때 다시 해시한다. 다운로드 실패는 기존 최종 파일을 바꾸지 않는다. 부분 파일이 잘못됐으면 제거하고 다시 시작한다.
- HTTPS 리다이렉트는 최대 6회 요청하고 HTTP로 내려가는 이동은 보내기 전에 거부한다. Range/Content-Range/크기/해시를 검사하며 사용자 취소와 30초 본문 읽기 만료를 지원한다. 최초 헤더 응답은 120초 제한이다. 프로세스 간 파일 잠금으로 동시 설치/삭제를 막는다. 디스크 부족은 일반 I/O 실패로 처리하며 사전 여유 공간 예약은 없다.
- CI가 고정 소스에서 만든 llama-server를 패키지에 포함한다. 플레이어에게 Python·Docker·Ollama·API 계정 설치를 요구하지 않는다. Windows/Linux x64는 AVX2/FMA/F16C, macOS는 Apple Silicon CPU 백엔드다. Intel Mac용 AI 실행 파일은 현재 포함하지 않는다. 기본 게임의 플랫폼 요구와 구분한다.
- 모델 파일은 Git/CI artifact에 넣지 않는다. 네이티브 실행 파일도 소스로 재빌드하며 Git에 바이너리를 커밋하지 않는다. [출처/라이선스](../../THIRD_PARTY_NOTICES.md), [실행 방법](../../BUILDING.md).

## 추론과 권한 경계

`LocalNpcRuntime`은 셸 없이 자식 프로세스 하나를 시작한다. 호스트는 127.0.0.1, 임시 포트와 세션별 난수 API 키를 쓰며 키를 명령줄/로그에 남기지 않는다. 환경의 LLAMA_* 설정을 제거하고 모델·스레드·오프라인 모드를 지정한다. 웹 UI/서브프로세스 도구/모델 자동 다운로드는 빌드/실행 옵션으로 끈다. 현재 GPU는 사용하지 않는다.

`LlamaNpcModel`은 llama.cpp의 apply-template → tokenize → completion을 호출한다. 검사한 토큰 배열 자체를 추론에 전달하고 입력 2,048 tokens·출력 96 tokens·HTTP 응답 32 KiB·전체 8초를 제한한다. 추론 결과는 JSON schema와 기존 `NpcDecisionGate`를 모두 통과해야 한다. 잘린 출력/컨텍스트 초과/위조 targetId/미지원 필드·의도는 거부한다. API 전송은 루프백만 허용하고 프록시/리다이렉트를 사용하지 않는다.

플레이어 원문은 추론 프로세스에만 보내고 디스크 대화 로그를 만들지 않는다. 요청/결과/의도 같은 메타데이터만 기존 로그에 남긴다. 다운로드 요청은 Hugging Face/CDN으로 보내지만 대화 입력을 포함하지 않는다. 로컬 모델도 CPU·RAM·전력을 사용하므로 “자원 부담이 없다”는 뜻은 아니다.

NpcMindService의 실행 슬롯 1개·대기 0개·8초 만료·세대/사실 재검증은 유지한다. 다운로드·해시·시작은 작업자에서 수행하며 게임 tick은 기다리지 않는다. 모델 오류나 만료 시 호스트의 기본 대사를 사용한다. Stop/종료에서 소유한 자식 프로세스를 종료하고, 시작 실패나 프로세스 중단 후 수동 재시작할 수 있다. 자동 무한 재시작은 하지 않는다. 일반 요청 취소는 HTTP를 취소하며, 서버가 멈춘 경우 Use basic dialogue/Start로 프로세스를 교체한다.

모델 출력은 **Greeting / QuestStatus / OfferInteraction 및 요청 NPC ID**만 허용한다. 모델이 의도를 잘못 분류할 수 있으므로 형식 검증을 정확도 검증으로 해석하지 않는다. 대사는 현재 게임 사실로 만들며 상호작용은 플레이어 확인과 Core 판정을 거친다. Core 규칙 v4·저장 스키마 v1·원본 리소스는 변경하지 않았다.

## 실제 모델 평가

공식 Qwen 두 모델을 실제로 다운로드하고 고정 SHA-256을 확인했다. 시험 입력은 저장소의 `tools/OpenD2.NpcEval/korean-intents-v1.json` 100개다. 인사/감사 20, 수락/완료 보고 30, 상태/거절 20, 미지원·비밀·중복 보상 요구 15, 지침 덮어쓰기 15로 고정했다. 정답은 호스트가 기대하는 의도이며 모델 응답과 비교한다. 평가 입력은 합성 자료이며 실제 플레이어 대화가 아니다.

이는 NPC-02a의 **의도 분류 시험**이다. 기억 복원·다중 플레이어 비밀 격리·자율 계획의 전체 100시나리오 인수와 다르다. 오류/길이/위조/만료/취소는 별도의 계약 시험으로 검사한다. 이 시험으로 자유 문장 사실성이나 초지능을 주장하지 않는다.

환경: Linux x64 개발 컨테이너, .NET에 논리 CPU 8개 노출, 추론 스레드 4개, llama.cpp CPU 백엔드. cgroup 한도는 CPU 8개·메모리 8 GiB다. 모델당 순차 100요청, temperature 0, seed 1, prompt cache 비활성, 출력 전체를 받은 시간을 측정했다. 스트리밍/첫 토큰 시간은 측정하지 않았다. 작은 모델 시험 중 큰 모델 다운로드가 진행됐으므로 완전히 격리된 성능 벤치마크가 아니다. 사용자 PC/3D 장면/GPU의 보증 수치로 사용하지 않는다.

| 모델 | 용량 | 유효 JSON | 의도 정답 | p50 / p95 완료 | 최대 |
|---|---:|---:|---:|---:|---:|
| Qwen3 0.6B Q4_K_M | 397 MB | 100/100 | **51/100** | 1.21 / 1.39초 | 1.57초 |
| Qwen3 1.7B Q8_0 | 1834 MB | 100/100 | **83/100** | 3.75 / 4.36초 | 4.65초 |

원자료: [0.6B CPU](evidence/npc02-qwen06-cpu.json), [1.7B CPU](evidence/npc02-qwen17-cpu.json). 각 문장의 예상/실제 의도·오류·시간과 모델/시험 파일 hash를 보존했다. 프롬프트는 두 평가 사이에 수정하지 않았다.

**판정: 두 모델 모두 일반 사용자용 기본 AI로 채택하지 않는다.** 더 큰 모델은 83%로 개선됐지만 상태/거절·지침 덮어쓰기 오분류가 남았다. 구조화 출력 100%는 사실성·의도 정확도나 공격 방어 100%를 뜻하지 않는다. 게임 권한 경계와 명시적 확인을 유지한다.

| 유형 | 0.6B 정답 | 1.7B 정답 |
|---|---:|---:|
| 인사/감사 | 20/20 | 20/20 |
| 수락/완료 보고 | 25/30 | 20/30 |
| 상태/거절 | 1/20 | 19/20 |
| 미지원 요구 | 0/15 | 14/15 |
| 지침 덮어쓰기 | 5/15 | 10/15 |

Q4와 Q8은 매개변수 수와 양자화가 함께 다르다. 결과 차이를 크기 하나의 효과로 단정하지 않는다. 다운로드 비용과 응답 지연까지 포함해 품질을 개선한 뒤 기본 추천 여부를 결정한다. 현재 기본값은 계속 스크립트 대사이며 두 모델은 실험/비교용이다.

이 환경의 Process.WorkingSet64 표본은 모두 0으로 반환돼 **RAM 측정 불가**로 표시한다. 모델 메모리가 0이라는 뜻이 아니다. 원본 행의 0 표본은 보존하고 보고서 집계값은 미측정으로 정규화했다. 연속 peak RSS·VRAM·게임 렌더링 병행 수치는 아직 없다.

## 검증과 남은 인수

로컬 실행형 계약 228/228: 기존 211개에 17개를 추가했다. 정확한 토큰 전달·형식/크기/완료 제한·취소 전파·루프백 계약, 실물 다운로드 없이 이어받기/잘못된 Range/HTTPS 하향 거부/리다이렉트 반복/해시/원자적 교체/잠금/취소, 모델 없는 기본 실행, 실제 네이티브 실행 파일의 버전 실행과 잘못된 GGUF 시작 실패·재시작 정리를 확인한다.

로컬 locked restore·전체 빌드·228개 계약·Godot import/헤드리스·Linux export를 통과했다. SDK 검색 경로를 제거한 Linux 배포본에서도 `OPEND2_NPC02_RUNTIME_READY`·`OPEND2_NPC01_DIALOGUE_READY`·tick marker를 확인했다. 네이티브 런타임은 실행하되 이 패키지 smoke에서 모델은 다운로드하지 않는다. 실제 모델 실행/의도 평가는 위 별도 CPU 시험이다.

처음 로컬 헤드리스 검사에서 Godot 편집기의 메모리 로드 때문에 Assembly.Location이 비어 있는 오류를 발견했다. 편집기 출력 경로를 명시하고 배포본에서는 AppContext.BaseDirectory를 사용하도록 수정해 다시 통과했다. x64 빌드에서 AVX2만 켜고 FMA를 끄면 해당 고정 ggml 소스가 컴파일되지 않아 FMA/F16C 요구를 명시하고 실행 전 CPU 검사를 추가했다.

Windows/macOS/Linux 원격 CI는 이번 변경 커밋에서 실행 예정이며 통과 전에는 완료로 기록하지 않는다.

Godot 4.6.3의 Android export 설정 조회/에디터 종료 경쟁 조건은 [NPC-01 기록](NPC_01_RESULTS.md)의 알려진 외부 제한이다. 이를 숨기거나 성공으로 처리하지 않는다. 이번 CI에 나타나면 정확한 실패와 재실행 결과를 기록한다.

NPC-02b 다음 작업:

1. 품질이 낮은 의도 분류를 개선하고 별도 미공개/신규 문장 세트로 재평가한다. 현재 100문장에 프롬프트를 맞춘 결과만으로 제품 품질을 확정하지 않는다.
2. Apple Silicon/Windows 목표 PC에서 CPU와 GPU 후보를 비교하고 실제 RAM/VRAM·첫 응답·전체 지연·렌더링 p95 악화를 측정한다. 패키지 서명/공증·실행 권한과 개발 도구 없는 설치도 인수한다.
3. 재시작/취소·지역 이동을 포함한 1시간 안정성, 메모리 회수와 프로세스 잔존을 측정한다. 현재 짧은 계약 시험을 장시간 검증으로 대체하지 않는다.
4. 이후 NPC-03에서 제한된 사건 기억·관계·목표와 저장 스키마 변환을 설계/구현한다. 모델을 바꾸더라도 거래·보상·퀘스트 권한은 Core에 둔다.
