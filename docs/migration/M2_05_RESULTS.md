# M2-05 저장·복원·복구와 원본 세이브 사전검사

검증일: 2026-10-08 UTC. 기준 master `2b8e1130143f36c5447220895495bc719373bc6a`, 작업 브랜치 `feat/m2-playable-slice`, 저장소 `imagineiluv-star/OpenD2`.

**자체 게임 저장·복원·이전 정상본 복구는 구현했다. 원본 세이브는 읽기 전용 사전검사까지이며 캐릭터/아이템 변환은 미구현이다. M2-05 전체 인수는 이 잔건 때문에 열려 있다.** NPC LLM은 [별도 도입 설계](NPC_LLM_DESIGN.md)를 추가했으며 모델 실행 코드는 이번 변경에 포함하지 않았다.

## 구현과 조작

`GameSimulation.Restore`는 현재 tick·난수·전체 지역의 객체/AI 상태·퀘스트·입력 순번·예약 명령·아이템 소유권/장비를 검증한 후 새 시뮬레이션으로 복원한다. 과거 입력을 처음부터 재생할 필요가 없다. 기존 Core 규칙 v4와 상태 hash 형식은 변경하지 않았다. 설치된 지도/콘텐츠는 저장 파일에 복제하지 않고 콘텐츠 hash로 일치 여부를 확인한다.

`GameSave`는 저장 스키마 1, 규칙 버전, 콘텐츠 hash, 상태 hash와 현재 상태를 JSON으로 보존한다. 최대 4MiB·JSON 깊이 32이며 입력/객체/아이템은 기존 Core 상한을 적용한다. 불변 지도 데이터는 호출자가 제공하며 다른 콘텐츠로 잘못 불러오지 않는다. hash는 손상 감지용으로, 오프라인 파일 변조를 막는 인증 서명이나 네트워크 권한 검증은 아니다.

Simulation 탭의 **Save checkpoint / Load checkpoint**를 사용한다. `AppPaths.Saves/simulation-v1.json`의 단일 슬롯이며 설치 폴더 밖 사용자 데이터 경로다. 저장/로드 중 게임을 일시 정지하고 파일 I/O와 검증은 백그라운드 작업으로 처리한다. 로드 전체가 성공한 뒤에만 화면의 게임 인스턴스를 교체한다. 성공 후에도 일시 정지 상태를 유지해 **Resume**으로 계속한다.

로드 시 재생 기준도 복원한 snapshot으로 바꾼다. 저장된 미래 입력은 유지하고 이후 입력만 기록한다. **Verify replay**는 해당 체크포인트에서 이어지는 재생을 검증한다. 10분/4,096개 기록 상한은 로드 시 새 기준으로 시작한다. 파일 저장 자체는 이전 플레이 시간만큼 재생하거나 과거 명령 전체를 저장하지 않는다.

## 복구·원자 교체 정책

1. snapshot의 객체·입력·아이템·퀘스트 관계와 상한을 검증하고 직렬화한다. 잘못된 입력은 기존 파일을 건드리기 전에 거부한다.
2. 슬롯의 `.lock` 파일을 `FileShare.None`으로 연다. 파일은 유지하고 OS가 프로세스 종료 시 잠금을 해제한다. 두 작성자가 같은 슬롯을 갱신하지 못한다.
3. 기존 주 파일이 정상이며 현재 스키마/콘텐츠와 맞으면 이전 정상본 `.bak`을 임시 파일→flush→같은 디렉터리 rename으로 교체한다.
4. 새 주 파일도 고유 임시 파일에 쓰고 `Flush(true)` 후 rename한다. 실패 시 해당 임시 파일을 정리한다. 프로세스 강제 종료가 남긴 임시 파일은 로드 후보로 사용하지 않는다.
5. 주 파일이 없거나 손상됐으면 백업 로드를 시도한다. 복구 여부를 반환/표시하고 원래 파일은 자동으로 수정하지 않는다. 양쪽이 손상되면 실패하며 새 게임을 정상 복구처럼 만들어 반환하지 않는다.
6. 미지원 스키마·규칙 또는 다른 콘텐츠는 손상으로 간주하지 않는다. 더 오래된 백업으로 조용히 되돌리거나 덮어쓰지 않는다. 주 파일이 손상되어도 백업이 미래 버전이면 저장을 중단한다.
7. 손상된 주 파일 위에 사용자가 다시 저장해도 기존 정상 백업을 손상 파일로 교체하지 않는다.

같은 디렉터리의 일반 로컬 파일시스템 rename을 전제로 한다. 백업과 주 파일 두 개를 한 번에 바꾸는 파일시스템 트랜잭션은 아니다. 파일 flush는 수행하지만 디렉터리 metadata의 전원 차단 내구성·NAS/클라우드 동기화 드라이브 의미론·실제 전원 차단 복구는 아직 인수하지 않았다. 쓰기 금지/디스크 부족 등 I/O 오류는 호출자에게 전달하며 UI의 기존 게임은 유지된다.

## 복원 검증

객체 ID 정렬/중복, 위치·충돌·체력·쿨다운·AI 대상, 죽은 객체 이동, 월드 플레이어/퀘스트 목표, 명령 커서·과거/과도한 미래 tick·중복 sequence·큐 예산, 아이템 출처·단일 소유권·슬롯 중복·종류/지역/좌표를 검사한다. 예약 명령은 제출 이후 플레이어가 죽었을 수도 있으므로 이를 보존하고 실행 tick에 기존 규칙대로 폐기한다. 비활성 지역의 몬스터가 다른 지역으로 떠난 플레이어를 대상으로 기억하는 유효 상태도 보존한다.

스냅샷 복원은 별도 인스턴스에서 수행하며 실패해도 라이브 게임을 부분 변경하지 않는다. 상태 hash를 마지막에 대조하고 향후 tick의 이벤트·hash가 저장 전 게임과 같은지 계약으로 검사한다.

## 원본 D2S 초기 범위

```sh
dotnet run --project tools/OpenD2.AssetAudit -- --inspect-save /path/to/character.d2s
```

`LegacySaveInspector`는 기존 C++ `Shared/D2Common_Shared.hpp`의 헤더 구조와 [dschu012/d2s의 header 구현](https://github.com/dschu012/d2s/blob/master/src/d2/header.ts), [기본 헤더 위치](https://github.com/dschu012/d2s/blob/master/src/d2/versions/default_header.ts)를 참고한 독립 C# 읽기 전용 검사다. 외부 라이브러리/코드를 포함하지 않는다.

- 버전 **96**만 허용, 335바이트 헤더 이상·1MiB 이하, magic·파일 길이·전체 rolling checksum·이름 종결/ASCII·class/level 범위를 검사한다.
- 이름·클래스 ID·레벨·expansion/hardcore/dead·파일 SHA-256을 출력한다. JSON에 `BodyValidated=false`, `ImportSupported=false`를 명시한다.
- 다른 버전/D2R·비ASCII 이름은 추측하지 않고 거부한다. v96은 특정 게임 패치와 일대일 대응하지 않으므로 1.10f 파일 호환 인수로 표시하지 않는다.
- 원본 파일을 수정/변환하지 않는다. 능력치 비트 스트림·아이템·스킬·퀘스트·용병 본문 검증과 실제 캐릭터로의 가져오기는 후속 범위다. 헤더/체크섬이 맞아도 완전한 유효 세이브라고 주장하지 않는다.

## 검증 결과

- 전체 Debug 솔루션 빌드 경고/오류 0. 최종 계약 **188/188** 통과(기존 164 + 저장 20 + 원본 헤더 4).
- 장비/퀘스트/비활성 객체/예약 입력/난수를 포함한 저장-로드 hash 일치, 이후 100tick 이벤트/상태 일치, 체크포인트 기준 재생을 검사했다.
- 손상 주 파일·백업 복구·둘 다 손상·checksum 변조·미지원 버전·콘텐츠 불일치·잘못된 필드/상한·복원 불변식·잠금 충돌·백업 교체 실패·임시 잔여 파일을 검사했다. 실패 주입은 실제 I/O 대상 충돌로 수행했으며 전원 차단 실험은 아니다.
- 원본 검사는 합성 v96 헤더와 독립 Python checksum 기준값으로 검증했다. 실제 사용자 `.d2s`는 제공받지 않았으며 검증하지 않았다.
- Godot import·헤드리스 시작·Linux self-contained export 성공. `OPEND2_M205_SAVE_READY`는 저장/재로드와 이전 정상본 복구를 검사한다. 최종 188개 계약과 플레이어 정체성 검사까지 반영한 코드에서 재검증했다.
- Linux SDK 없는 배포 smoke도 종료 코드 0으로 모든 준비 마커를 출력했다. 최종 기능 브랜치/PR CI의 Linux·Windows·macOS도 모두 통과했다.

```sh
python eng/validate.py --export Linux
env -u DOTNET_ROOT -u DOTNET_ROOT_X64 PATH=/usr/bin:/bin \
  ./artifacts/Linux/OpenD2.x86_64 --headless --quit-after 120 -- --smoke-test
python eng/verify.py
git diff --check
```

초기 원격 Windows CI에서는 백업 경로를 디렉터리로 막은 실패 주입에서 `UnauthorizedAccessException`이 반환됐으나 테스트가 `IOException`만 기대해 1건 실패했다. 테스트를 두 OS 오류 형식을 허용하도록 수정했고, 실패 여부·주 파일 byte 보존·임시 파일 정리는 계속 엄격하게 검사한다. 런타임 저장 로직을 완화하지 않았다.
