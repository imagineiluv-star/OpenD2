# PLAY-16 — 회복 물약과 벨트 기초

기준 master: `010c04b` (PLAY-15). 브랜치: `feat/play-16-potions-belt`.

## 구현

마나/체력이 줄어든 뒤 사용할 소모품과 단축 슬롯이 없었다. 이번 단계는 엔진 독립 Core에서
전리품·소유권·회복·소비를 처리하고 기존 가방과 4칸 벨트 UI에 연결한다. 중앙 서버나 별도 런타임은 추가하지 않는다.

- HealthPotion은 HP 40, ManaPotion은 MP 30을 즉시 회복한다. 상한까지만 적용하고 실제 회복량을 이벤트로 알린다.
  상한/0 최대마나·권한·위치·tick 시작 기절·사망 검사에서 실패하면 소비하지 않는다. 성공은 한 플레이어당 tick에 한 번이다.
  같은 ID의 재사용과 다른 물약을 이용한 동시 사용을 막되, 실패한 요청은 그 tick의 성공 기회를 소모하지 않는다.
- 기존 아이템 명령 단계(전투 판정보다 앞)에서 회복한다. 같은 tick의 뒤쪽 공격보다 먼저 회복할 수 있다.
  이미 죽은 플레이어의 예약 명령은 건너뛴다. 이동/공격을 취소하거나 전투 RNG를 소비하지 않는다.
  마나가 가득 차면 회복 누적 tick도 0으로 정리한다.
- 새 몬스터의 생존→사망 전환마다 기존 장비 한 개와 물약 한 개를 생성한다. 짝수 몬스터는 체력, 홀수는 마나 물약이다.
  원본 드롭 표가 아닌 preview 규칙이다. 처음부터 죽어 있는 몬스터/이전 저장의 사망 몬스터에는 소급 생성하지 않는다.
- 기존 장비 ID는 유지하고 물약 ID는 `2^32 | monsterId`를 쓴다. ItemId를 ulong으로 넓혀 전체 uint 몬스터 ID와 충돌하지 않는다.
  소비된 물약은 소유자/슬롯/위치를 비운 Consumed 기록으로 남는다. 아이템 배열은 최대 `2 × entities`이고,
  추가 드롭 이벤트에 맞춰 고정 이벤트 예산을 늘렸다. tick 내부 새 할당/파일 I/O는 없다.
- 물약은 고정 1×1이며 InventoryLayout의 장비 두 정의/ContentHash를 바꾸지 않는다.
  장면 identity와 이전 장비 크기/코드를 유지한다. 원본 TXT의 물약 효과/크기 바인딩은 아직 지원하지 않는다.
- BeltItem은 가방/벨트→4칸 벨트 이동·교환이다. 차 있는 칸은 원래 가방 칸 또는 벨트 칸과 원자 교환한다.
  MoveItem은 벨트→지정 빈 가방 칸, Unequip은 first-fit 복귀, DropItem은 벨트에서 바닥으로도 가능하다.
  가방의 찬 칸으로 되돌리기/가방 부족·장비의 벨트 배치는 거부하고 원래 위치를 보존한다.
- UseItem은 소유한 가방/벨트 물약 ID, UseBelt는 tick 실행 당시 슬롯의 물약을 사용한다. payload·지역·행동 주체도 기존 검증을 따른다.
  좌표/이동 출처/저장 슬롯 검사를 switch로 분리해 새 명령마다 긴 삼항식을 늘리지 않도록 정리했다.

## 조작과 표시

- F로 바닥 아이템을 하나씩 줍고 가방에서 Drink selected potion으로 사용할 수 있다.
  같은 위치의 장비와 물약은 작은 ID(기존 장비)부터 줍는다. 이름 선택 줍기는 다음 단계다.
- 가방/벨트 드래그 또는 물약 선택→목적 슬롯→Put selected in belt로 배치한다.
  벨트 클릭은 선택이며 Use 버튼/게임 화면의 숫자 1–4는 누를 때 한 번 사용한다.
- 상태 메시지에 실제 회복량·빈 슬롯·자원 포화·기절 등을 표시한다. 소비 뒤 아이콘/선택/슬롯을 비운다.
  메뉴/확인/파일 검증/사망 중 조작을 막고, 일시정지 중에는 물약 사용을 막는다.
  이전 세션의 drag payload는 거부한다. 배치 명령은 기존 인벤토리와 같이 일시정지 중 예약할 수 있다.
- Scene art에 HealthPotion/ManaPotion 아이콘 항목이 생긴다. 명시적인 DC6/팔레트/프레임을 선택하며
  미설정 항목은 이름으로 표시한다. 회복 효과음은 기존 Loot cue를 재사용하며 전용 원본 소리는 별도다.

## 저장 호환

현재 **schema 4 / rules 7**은 64bit 아이템 ID, Belt/Consumed 위치와 새 명령을 저장/hash한다.
이전 schema/rules 쌍 **1/4, 2/5, 3/6**만 명시적으로 변환한다.

1. 원래 32bit ID의 v4/v5/v6 checksum·콘텐츠·소유권·가방·명령 큐를 먼저 검증한다.
   이전 형식에 물약 ID/새 위치/새 명령이 섞이면 거부한다.
2. v1은 기존 가방 패킹과 마나 기본값, v2는 기존 배치 및 마나 기본값, v3는 기존 배치·마나·선택·대기·회복 누적을 유지한다.
   기존 물건을 물약으로 바꾸거나 소급 드롭을 만들지 않는다.
3. 로드는 파일을 쓰지 않는다. 명시적 저장에서만 현재 형식으로 원자 교체하고 이전 정상 파일을 1세대 `.bak`에 남긴다.
4. 미래 버전/다른 콘텐츠·크기/패킹 공간 부족은 호환 오류로 두 파일을 보존한다.
   손상 주 파일은 정상 백업을 검증/변환한다. 구형 전체 replay 엔진이나 원본 `.d2s` 본문 변환은 아니다.
