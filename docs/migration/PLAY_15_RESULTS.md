# PLAY-15 — 마나와 첫 능동 스킬

기준 master: `df27034` (PLAY-14). 작업 브랜치: `feat/play-15-mana-skill`.

## 구현

전투에 자원과 스킬 발동 경로가 없어 일반 공격만 사용할 수 있었다. 이번 단계는 Core에
마나·선택·발동을 추가하고 클라이언트/HUD 및 저장·재생에 연결한다. 별도 중앙 서버나 서비스는 필요하지 않다.
첫 스킬은 **Power strike(강타)**라는 preview 근접 공격이며 원작 스킬 수치를 이식한 것은 아니다.

- `EntityState`: Mana/MaxMana(기본 60), SkillCooldown, ManaRecoveryTicks, SelectedSkill(None/PowerStrike).
  초기화/복원에서 범위와 포화 상태를 검사하고 모두 rules 6 상태 hash에 포함한다.
- 선택 명령은 X에 SkillId, 발동 명령은 Target에 상대 ID를 담는다. enum은 기존 값 뒤에 추가한다.
  명령 순서대로 선택을 처리하고 발동 당시 선택을 캡처한다. 같은 tick의 공격/스킬은 마지막 하나만 실행한다.
  미리 제출한 큐도 동일 검증을 통과해야 한다. 사망·비플레이어·다른 지역/대상·잘못된 payload는 거부한다.
- 강타는 기존 근접 사거리 384, 무기 피해 +12, 마나 비용 12, 자체 대기 25 tick(1초)다.
  일반 공격 대기도 12 tick으로 설정한다. 기존 피격 중단→일반 대기→대상 생존→거리→벽 검사를 공유하고
  선택/자체 대기/마나를 검사한 뒤에만 RNG와 비용을 소비한다. 기절이 끝나는 바로 그 tick은 기존 규칙대로 행동할 수 없다.
  같은 tick에서 먼저 처리된 적의 피격도 발동을 막는다. 성공한 스킬은 이동/상호작용을 중단하고 기존 사망·전리품·퀘스트 경로를 쓴다.
- 활성 지역의 살아 있는 플레이어는 tick 시작 때 25 tick마다 마나 1을 회복한다. 기절 중에도 회복한다.
  최대치에서 누적은 0이며 성공 발동도 회복 누적을 0으로 재시작한다. 사망/비활성 지역은 자원 갱신을 멈춘다.
  현재 몬스터는 자원 필드를 사용하거나 회복하지 않는다. 메뉴/일시정지는 시뮬레이션 tick을 멈춘다.
- preallocated combat intent 배열을 사용하며 tick 내부 파일 I/O/새 할당이 없다. 실패한 명령도 기존 이벤트 예산 안에서 처리한다.
- 스킬 선택 목록, Q/버튼으로 가장 가까운 적 발동, MP 수치/바·부족/대기 안내를 추가한다.
  Q는 누를 때 한 번이며 자동 접근/반복 시전은 하지 않는다. 메뉴/확인/검증/일시정지/사망 중 UI 입력은 막는다.
  강타의 표현은 기존 Attack 애니메이션 및 Attack/Hit 효과음 경로를 사용한다.
- HUD의 선택 Mana 역할은 Health와 독립적으로 DC6를 아래부터 채운다. 하나만 허용하고 클릭 동작은 없다.
  없는 장면에는 기본 마나 바가 남는다. Scene art의 50% 미리보기에도 연결했다.

## 저장과 장면 호환

새 파일은 **schema 3 / rules 6**이다. 자원 필드를 모두 요구하고 checksum에 포함한다.
지원하는 구형 파일은 **schema 1/rules 4**, **schema 2/rules 5**다.

1. 콘텐츠·이전 상태/명령 큐·v4/v5 checksum을 먼저 검증한다. 구형 파일에 새 자원 필드를 끼워 넣으면 거부한다.
2. v1은 기존 10×4 가방 변환을 수행하며 공간 부족은 호환 오류로 보존한다. v2는 배치를 재정렬하지 않는다.
3. 검증 후에만 마나 60/60, 대기/누적 0, 선택 PowerStrike를 명시적으로 부여한다.
   JSON에서 생략된 구조체 필드가 생성자 기본 인자를 받는다고 가정하지 않는다.
4. 로드에는 파일 쓰기가 없다. 다음 명시적 저장 때 기존 정상 파일을 `.bak`으로 남기고 원자 교체한다.
   백업은 1세대 회전이다. 미래 버전/다른 콘텐츠·크기/공간 부족은 오래된 백업으로 조용히 대체하지 않는다.
5. 기존 장면 해시의 배우 직렬화 모양을 고정해 새 상태 필드가 기존 scene identity와 저장 슬롯 경로를 바꾸지 않게 했다.

구형 전체 replay 엔진을 유지하는 것은 아니다. 검증된 checkpoint 이후에는 현재 규칙을 쓴다.
원본 `.d2s` 본문 이관과도 별도다. 구버전 앱은 v3 저장을 읽을 수 없다.
