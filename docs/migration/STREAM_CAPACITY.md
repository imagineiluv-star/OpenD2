# 32개 WSS 연결과 다중 방 인수

`eng/check-capacity.py`는 실제 self-contained 서버와 production `OnlineClient`를 사용해
Realm/Open 각각 **8개 방 × 4명 = 32개 동시 WSS 연결**을 검사한다. 33번째 계정은 별도 대기 방의
연결 상한 검사에 사용한다. 테스트 전용 .NET 클라이언트이며 일반 Godot의 PC당 한 클라이언트
정책은 변경하지 않는다. 시스템 CA 저장소도 변경하지 않는다.

```sh
dotnet publish src/OpenD2.Server -c Release -r linux-x64 --self-contained true -o artifacts/network-server -m:1
python eng/check-capacity.py --server-exe artifacts/network-server/OpenD2.Server --seconds 30
```

Windows는 `win-x64`와 `.exe`, Apple Silicon macOS는 `osx-arm64`를 사용한다.
`--seconds`는 모드별 지속 관측 구간(1–3600초, 기본 30초)이다. 설정·전투 준비·연결 회수 시간은
별도다. 기존 등록/방 입장 예산 60회/분을 유지하며, 설정 중 명시적인 429 응답을 받은 요청만
61초 대기 후 한 번 재시도한다. 입력은 자동 재시도하지 않는다. 두 모드 실행에는 설정 대기로
보통 수 분이 추가된다. CI는 기존 3 OS 패키지 작업 안에서 모드별 5초를 검사한다.

## 자동 판정

1. 8개 방의 각 4명에게 올바른 방 ID·배우·호스트 여부·캐릭터 구성의 전체 기준 프레임이 도착한다.
2. 32개 연결이 유지되는 동안 33번째 WSS는 429로 거부된다.
3. 현재 v3 관심 범위를 협상하고 모든 클라이언트의 중립 이동 입력 순번이 정확히 1씩 증가한다.
   각 방 4명에게 공통으로 도착한 입력 이후 tick의 전체 상태 해시와 파티 배우·소유 아이템 값이
   일치하고 변경분이 수신된다. 일반 HTTP도 계속 응답한다. v3의 비파티 배우·바닥 아이템 배열은
   수신자별로 다를 수 있으며, 부분 수신 상태에서 전체 상태 해시를 다시 계산하지 않는다.
4. 하나의 WSS를 해제하면 다른 세션이 전체 프레임부터 연결할 수 있다. 다시 32개가 되면 추가
   연결은 거부된다. 클라이언트 해제와 서버의 정리 사이에는 최대 10초의 제한된 대기를 둔다.
5. 전체 연결을 해제한 다음 같은 32개 세션이 다시 연결된다. 전체 기준 프레임·입력 순번으로
   전역 슬롯 또는 세션 예약 누수를 검출한다.
6. 여유 슬롯이 있을 때 다른 방의 구독을 403으로 거부한다. 방 종료가 남은 모든 구독자에게
   404를 전달하고 스트림을 끝내는지 확인한다.

측정 전 가까운 공격자는 정상 전투 명령으로 처치한다. 지속 구간은 중립 입력·스트림 전달 검사이며
전투 부하 시험이 아니다. HTTP 입력은 최대 4개 동시 요청으로 기존 8개 요청 제한 안에서 실행한다.
HTTP 상태 조회는 준비 과정에만 사용하고 지속 관측에서는 WSS를 사용한다.

## 결과와 한계

`artifacts/online/capacity/run-<id>/result.json`에 커밋·dirty 여부·서버 실행 파일 SHA-256·시각과
두 모드 결과를 기록한다. `capacity-realm.json`, `capacity-open.json`에는 6단계 판정,
실제 관측 시간·입력 수·방별 공통 tick 일치 횟수·프레임 수·슬롯 회수 시간·설정 중 제한 대기 횟수,
최근 최대 4096개 HTTP 응답 시간의 p50/p95/max를 기록한다. 실패나 단계 누락은 FAIL과 nonzero다.
비밀 키·PFX·암호·계정 DB는 임시 경로에서 정리하며 결과물에 포함하지 않는다.

이 결과는 한 실행 환경에서 **설정된 32개 연결 제한의 기능 검증**이다. 최대 수용 인원, 성능 SLA,
실제 서버 CPU/GC/tick 실행시간, 지속 전투·송신 버퍼 포화·혼잡 제어 성능을 입증하지 않는다.
실제 두 PC·WAN·IP 패킷 손실·수동 GUI·2시간 장시간 인수는 계속 **NOT_RUN**이다.
`--seconds` 값을 늘리는 것만으로 이런 항목을 PASS로 바꾸지 않는다.
