# ONLINE-07: Realm과 개인 호스트 동등 지원

2026-10-10 사용자 확정: Diablo II의 두 운영 방식을 모두 지원한다.
이는 자체 OpenD2에서의 운영/플레이 흐름 지원이며 Blizzard 계정·Battle.net 프로토콜 호환을 뜻하지 않는다.
두 모드는 같은 게임 규칙·리소스·전투 코어를 공유한다. 지금의 4인 전투장만으로 원작 게임 전체 지원을 선언하지 않는다.

| 항목 | Realm / 운영자 서버 | Open / 개인 호스트 |
| --- | --- | --- |
| 서버 실행 | 운영자 상시 서버 | 방장 PC의 별도 서버 프로세스 |
| 접속 흐름 | 서버/지역 → 계정 → 서버 캐릭터 → 방 | 개인 캐릭터 → 방 만들기 또는 LAN/주소/초대로 참가 |
| 캐릭터 권위 | 서버 저장이 정본 | 개인 저장을 사용하는 별도 신뢰 영역 |
| 방장 종료 | 서버와 방 정책에 따라 유지 | 호스트 종료 시 방 종료; 자동 호스트 이전은 초기 범위 밖 |
| 인터넷 경로 | 공개 서버로 외부 연결 | 직접 연결 가능 여부 확인, 필요 시 포트 매핑/중계 |
| 일반 PC | 클라이언트 하나 | 클라이언트 하나, 호스트일 때 서버 추가 |

## 구현 순서와 승인 기준

1. 모드/저장 경계: Realm과 Open 프로필·인벤토리·진행 파일을 분리하고 서로 반입을 거부한다.
   Open 서버가 받은 캐릭터는 크기·스키마·아이템·좌표 등을 검증한다. 개인 호스트를 운영 서버만큼
   신뢰할 수 있다고 표시하지 않는다. 기존 계정/서버 데이터의 호환성과 마이그레이션을 검사한다.
2. 호스트 수명: 동일 버전 서버 패키지를 클라이언트에서 시작하고 준비 확인 후 자기 방에 접속한다.
   포트 충돌, 서버 시작 실패, 호스트 종료·강제 종료, 데이터 저장 실패를 명시적으로 처리한다.
   게임 클라이언트의 PC당 하나 제한을 서버에 잘못 적용하지 않는다.
3. LAN 참가: 주소 입력부터 구현하고 같은 방에서 이동·전투·아이템·재접속·캐릭터 저장을 검증한다.
   원격 평문 HTTP 차단을 해제해서 해결하지 않는다. TLS 신뢰 설정 또는 인증된 전송 경로가 필요하다.
4. 인터넷 참가: 방 검색/초대 서비스와 게임 데이터 경로를 분리한다. 직접 연결 가능하면 직접 연결,
   NAT/CGNAT 때문에 불가능하면 지원되는 중계 경로와 상태를 안내한다. UPnP/PCP 지원 여부·
   CGNAT·이중 NAT·차단 UDP를 구분한다. 매핑은 사용자에게 공개하고 생성한 매핑만 회수한다.
   기술 후보의 프로토타입/실측 후 채택하며 현재 자동 매핑·홀펀칭·중계 구현은 없다.
5. UI/배포: 시작 화면에서 두 모드를 명확하게 선택하고 호스트/참가, 주소/초대, 경로 상태,
   저장 위치/연결 끊김을 안내한다. 각 OS 클라이언트+서버 패키지의 버전/해시를 검증한다.
6. 공통 기능: 전투·아이템·퀘스트·MPQ 월드·음성 채널을 두 모드에 연결한다. 방 검색 서비스
   장애와 게임 호스트 장애를 구분하고 음성 중계 비용·실제 장치를 별도로 검증한다.

## 검증 완료의 의미

- 자동: 세 OS의 압축/해제/실행, 정상 클라이언트 중복 차단, 호스트 프로세스 충돌/종료,
  두 클라이언트 같은 방의 플레이/저장, 모드 간 데이터 거부, 인증서·세션·권한, 로그 오류 검출.
- 실제 장치: PC마다 일반 클라이언트 하나. 두 모드 각각 LAN과 서로 다른 인터넷 회선에서
  방 만들기/참가·장시간 플레이·재접속·호스트 종료, 화면 입력과 음성을 별도 기록한다.
- 경로: 직접·포트 매핑·중계와 NAT 유형, 지연/손실/트래픽을 기록한다. 자동 렌더링이나
  loopback 두 프로세스 시험을 실제 두 PC 검증으로 대신하지 않는다.

현재: 전용 서버 계정/캐릭터/방·HTTPS/WSS·서버 저장 모드 경계, Open 아이템 파일과
같은 PC/LAN 개인 호스트 시작/종료 UI·자동 프로세스 관리 구현.
미완료: Open 퀘스트·레벨·스킬 이관/동기화·인터넷 제품 흐름,
공개 Realm 배포/자동 배정, 실제 LAN/WAN/GUI/음성 인수.

원작 참고: https://classic.battle.net/diablo2exp/faq/realms.shtml
및 https://classic.battle.net/diablo2exp/faq/multiplayer.shtml .

## 구현된 기반: 서버 모드와 저장 경계

서버 `--mode realm`(기본)과 `--mode open`을 구분하고 기본 데이터 폴더를 각각
`realm-data`, `open-data`로 선택한다. `--data`로 경로를 지정해도 저장 모드가 다르면
시작을 거부하며 원본 데이터 파일을 덮어쓰지 않는다. 알 수 없는 모드는 폴더 생성 전에 거부한다.

새 데이터는 형식 2와 명시적인 `Mode`를 기록한다. 형식 1의 기존 데이터는 Realm으로만
열리고 다음 저장 때 형식 2로 변환된다. **기존 운영 데이터를 업그레이드하기 전에 별도 백업한다.**
형식 2를 이전 서버 버전으로 열 수 없으므로 롤백에는 이전 백업이 필요하다. 형식 2의 모드가
누락되거나 유효하지 않으면 거부한다. 모드 라벨은 실수 방지 경계이며, 파일을 직접 수정하는
개인 호스트를 신뢰 가능한 운영 서버로 바꾸거나 치트를 방지하는 암호학적 보증이 아니다.

`/health`의 `mode`와 `OnlineClient`의 선택 모드를 로그인 전에 비교한다. Godot UI의 Realm/Open 선택값과 서버 모드가 다르면 접속을 거부한다. 테스트/개발 클라이언트는
`new OnlineClient(address, caFile, "open")`으로 명시한다. 기존 모드 필드가 없는 서버는
Realm으로 간주해 호환성을 유지하되 Open 클라이언트로 접속하지 않는다.

`--mode open`은 아직 개인 호스트 제품 모드가 아니다. 현재는 분리된 계정/캐릭터/방 저장소를
갖는 서버 기반이다. 아래 API는 이름·승리 횟수와 현재 합성 가방·장비·벨트 아이템을 이관한다. 직업·레벨·퀘스트·원본 캐릭터 전체 호환은 아직 없다. 기존 원격 HTTPS 필수 조건,
인증서 검증, WSS 권한 검증과 클라이언트 PC당 하나 제한을 유지한다.

자동 검사: 양방향 데이터 모드 오용 거부·원본 유지·잠금 해제 후 재개방, 형식 1 이관,
형식 2 모드 누락/오류 거부, 실제 TLS 서버의 양방향 클라이언트 모드 불일치 거부와
Open 모드 로그인/캐릭터/방/WSS 수신. 완전한 두 모드 GUI 플레이 통과를 뜻하지 않는다.


## Open 캐릭터 파일 이관 (이름·승리 횟수·소유 아이템·퀘스트 완료 기록)

인증된 Open 사용자는 `GET /v1/characters/{id}/export`로 자신의 방 밖 캐릭터를 내보내고,
`POST /v1/characters/import`로 개인 프로필을 가져올 수 있다. Realm은 두 API를 모두 403으로
거부한다. 원본 계정/캐릭터 ID, 세션, 비밀번호는 파일에 포함하지 않는다. 반입은 새 서버 ID를
부여하고 현재 로그인 계정에 귀속한다. 기존 이름(대소문자 무관)이나 4개 제한에 걸리면 거부하며
기존 캐릭터를 덮어쓰지 않는다. 같은 프로필을 다시 반입하는 것은 갱신/동기화가 아니다.

형식 3 JSON은 `version: 3`, 현재 `rules`, `mode: "open"`, `name`, `victories`, `inventory`, `quests`를 포함한다.
`quests`는 `{ world, completions }` 목록이며 월드 콘텐츠 ID별 공유 퀘스트 완료 횟수다([M5-01d-1](M5_01D1_RESULTS.md)).
최대 8개, 월드 ID는 `[a-z0-9-]{1,64}`, 횟수는 1–1,000,000이고 중복 월드는 거부한다. 서버의 `realm.json`과 같은 검사를 쓴다.
46개 아이템과 8개 기록을 모두 채워도 8 KiB 한도 안에 들어간다.
각 아이템은 `definition`, `location`, `slot`만 저장한다. 서버 계정/캐릭터 ID, 방별 아이템 ID·소유자·좌표는
포함하지 않는다. 가방 40칸·장비 2칸·벨트 4칸의 최대 46개, 파일과 HTTP 요청은 기존 8 KiB 한도를 유지한다.
Core 규칙으로 정의·칸 겹침·격자 밖 배치·장비 종류·벨트 슬롯을 검사하고 바닥/소모 아이템은 거부한다.
필수 필드 누락, null 아이템, 중복/추가 JSON 필드, 잘못된 버전/모드/규칙도 거부한다.

형식 1(규칙 7/8)의 이름·승리 횟수 파일과 형식 2(아이템) 파일은 원본을 수정하지 않고 빈 기록 목록의 형식 3으로 메모리에서
이관한다. 형식 1·2 파일에 `quests`가 있거나 형식 3 파일에 `quests`가 없으면 형식과 내용이 어긋난 파일로 보고 거부한다.
형식 2·3은 규칙 8만 받으며 저장 시 항상 형식 3을 쓴다. 이름은 3–24 ASCII, 승리는 0–1,000,000 범위다.
Open의 편집 가능한 개인 파일을 Realm의 신뢰된 데이터로 취급하지 않는다. 파일 반입은 새 복사본이며
동기화나 글로벌 복제 방지가 아니다. 서버 간 반복 복사는 가능하고, 같은 계정의 중복 이름은 거부한다.
`/health.characterFileVersion: 3`을 로그인 전에 확인하여 구형 Open 서버의 아이템·퀘스트 기록 누락을 방지한다.
서버/클라이언트는 같은 빌드를 사용한다.

개발 클라이언트는 Open 모드로 로그인한 뒤 `ExportCharacter(id, path)`와
`ImportCharacter(path)`를 사용한다. `OpenCharacterFile.Save/Load`는 동일 검증을 적용한다.
저장은 같은 폴더의 임시 파일을 완전히 기록한 후 이동하며, 기존 목적 파일은 덮어쓰지 않는다.
새 스냅샷 파일명을 사용한다. 서버는 클라이언트 파일 경로를 받지 않는다.

**현재 합성 아이템·배치와 퀘스트 완료 횟수까지 이관하며 직업·레벨·개인별 퀘스트 진행·스킬·원본 `.d2s` 전체 캐릭터는 지원하지 않는다.**
완료 기록은 Open의 편집 가능한 개인 파일에 담기므로 승리 횟수와 같이 신뢰할 수 없는 값이다. Realm은 반입/반출 자체를 거부하므로
이 값이 Realm의 신뢰된 데이터로 들어가지 않는다.
갱신 충돌 해결/자동 동기화, 호스트 자동 시작·충돌 복구와 원본 캐릭터 인수는 후속 단계다.

검사: 로컬 파일 왕복·기존 파일 보호·잘못된 JSON/초과 크기, 무인증/다른 소유자/Realm 거부,
방 안 내보내기 거부, 중복 이름/개수 제한, 거부 시 DB 불변, 서버 재시작 후 유지,
실제 TLS의 파일 내보내기→다른 계정 반입→재내보내기 비교. GUI/실제 두 PC는 별도 미실행이다.


## Godot Open 접속 및 프로필 화면

온라인 화면의 `Realm — server characters` / `Open — personal profiles (preview)`에서
운영 방식을 선택한다. 서버 주소와 인증서 신뢰는 기존 정책을 그대로 사용한다. 로그인 후에는
모드 선택이 잠기고, 로그아웃해야 바꿀 수 있다. Open 서버는 별도 터미널/프로세스로 먼저
실행해야 한다. 이 화면이 호스트 자동 시작이나 인터넷 연결 설정을 대신하지 않는다.

Open 로그인 후 방 밖에서 `Import Open profile` / `Export Open profile`을 선택한다.
파일 선택 화면에 이름·승리 횟수·소유 아이템 포함과 새 복사본 정책을 표시한다. 가져오기가 성공하면 새 캐릭터를
자동 선택한다. 내보내기는 새 파일명을 사용해야 하며 기존 파일을 덮어쓰지 않는다.
파일 선택 중 로그인 세션이나 내보낼 캐릭터가 바뀌면 작업을 거부한다.

패키지 CI는 각 OS에서 추가로 Open TLS 서버와 두 Godot 클라이언트를 실행한다.
화면과 공유하는 파일 작업/캐릭터 선택 바인딩을 검사하고 기존 전투·아이템·재접속·강제 서버
재시작·방 종료 검사를 Open 모드에서도 수행한다. 파일 대화상자 직접 조작과 수동 GUI 플레이,
실제 두 PC 검증은 미실행이며 자동 바인딩 검사와 구분한다.

## 구현: 방 간 인벤토리와 규칙 8 이관

Realm/Open 모두 방을 닫을 때 각 캐릭터가 소유한 가방·장비·벨트 아이템을 저장한다.
바닥에 버린 아이템과 소모된 물약은 다음 방에 반입하지 않는다. 다음 방은 새 플레이어 번호에
소유권을 연결하고 방 전용 ID를 새로 부여한다. 이전 방의 몬스터/플레이어 ID는 반입하지 않는다.
방 삭제와 캐릭터 인벤토리 저장은 같은 DB 파일 교체에서 커밋한다. 쓰기 실패 시 접속을 닫는
기존 정책을 유지하며, 서버 재시작 시 마지막 정상 체크포인트에서 복원한다.

Core의 기존 장비/물약 드롭 ID 영역(0/1)은 유지하고 반입 아이템은 별도 영역 2를 사용한다.
ID는 방 범위이며 글로벌 거래 ID가 아니다. 반입은 빈 새 게임에서만 허용하고 최대 256개로
제한한다. 기존 드롭 용량과 별도로 공간을 확보해 꽉 찬 가방을 반입한 뒤 새 몬스터를 잡아도
배열 용량을 넘지 않는다. 알 수 없는 아이템/소유자, 겹친 칸, 잘못된 장비/벨트 배치와 초과
예산은 새 시뮬레이션 생성 전에 거부한다. 기존 몬스터 드롭의 출처/사망/정의 검증은 유지한다.

저장은 schema 5 / rules 8이다. 기존 schema 1–4 오프라인 저장과 rules 7 온라인 방은
원래 규칙의 체크섬/구조를 먼저 검증한 뒤 이관한다. 읽기만으로 파일을 덮어쓰지 않는다.
오프라인 저장의 다음 쓰기는 이전 파일을 백업한다. **운영 서버 DB는 업데이트 전에 직접
별도 백업한다.** 새 저장 파일은 옛 서버/클라이언트로 열 수 없으며 롤백에는 이전 백업이 필요하다.
규칙 7의 이름·승리 횟수 Open 프로필도 읽을 수 있다. 실시간 접속/기록 재생의 규칙 불일치는
기존대로 거부하며 구버전 클라이언트를 새 서버와 혼합하지 않는다.

검사: 기존 4개 기준 해시의 rules 7 바이트를 독립 Python little-endian 직렬화로 재현하고,
규칙 숫자만 8로 바꾼 해시를 고정했다. 이전 바이너리로 생성한 schema 4 예제에서 소모 기록·
벨트·대기 명령·원본 파일/백업을 확인한다. 규칙 7 온라인 방 복원/손상 체크섬 거부, Realm/Open
장비 이월·버린 아이템 제외·실행 중 재시작·방 닫기 저장 실패/복구·연속 방 이동, 두 Godot 클라이언트가 실제 획득한
아이템으로 새 방을 시작하는 검사를 추가했다.

미완료: Open 개인 파일 자동 동기화, 글로벌 거래/복제 방지 모델, 캐릭터 퀘스트·
레벨·스킬 영속화, 실제 두 PC/수동 GUI/WAN 인수. 현재 합성 장비/물약만
지원하며 원본 Diablo II 아이템 규칙이나 전체 캐릭터 호환을 뜻하지 않는다.

## Open 아이템 파일 검증 범위

- 46개 가방/장비/벨트 파일 왕복과 구형 형식 1 읽기, 원본·기존 저장 파일 보호.
- 유효하지 않은 정의/장비/벨트·칸 겹침·경계·null·예산 초과를 저장 변경 전에 거부.
- 서로 다른 Open 서버 저장소의 새 캐릭터 생성·서버 재시작·새 방 입장과 아이템 소유권 재연결.
- 실제 TLS 요청의 46개 파일 반입·새 방 입장, 필수 필드 누락/잘못된 장비 거부.
- 두 Godot 클라이언트의 실제 전투 후 획득 아이템을 UI와 같은 내보내기/가져오기 경로로 복사하고
  새 방에서 내용·배치를 확인. `OPEND2_OPEN_ITEM_FILE_PASS`를 두 클라이언트 모두 요구한다.
- 수동 파일 대화상자·실제 두 PC·WAN·청취/음성 검증은 NOT_RUN이며 자동 검사와 구별한다.


## 개인 호스트 시작·종료 UI (같은 PC)

Online 화면의 `Choose server`로 같은 OS용 서버 패키지를 압축 해제한
`OpenD2.Server`(Windows는 `.exe`)를 선택하고 `Start personal host`를 누른다.
로그아웃 상태에서 시작하며, Open 모드와 할당된 루프백 주소를 자동 선택한다.
계정 등록/로그인 → 캐릭터 → 방 흐름은 기존과 같다. 서버 실행 파일은 신뢰하는
OpenD2 빌드만 선택한다. macOS/Linux에서는 실행 권한이 필요하다.

데이터는 클라이언트 `user://personal-host/open-data`에 보관하며 실행 상태 옆에
실제 경로를 표시한다. 실행 파일 교체나 호스트 종료로 데이터를 삭제하지 않는다.
`Stop personal host` 확인 후 서버를 정상 종료하고 해당 호스트의 로그인 상태를
해제한다. 클라이언트를 닫아도 소유한 서버 프로세스를 종료한다. stdin 파이프가
끊어지면 서버가 종료되므로 클라이언트 비정상 종료에도 부모 없는 서버를 남기지
않는다. 정상 종료는 방 체크포인트를 저장하며, 재시작 후 다시 로그인/참가한다.
10초 안에 종료하지 못하면 소유한 프로세스만 강제 종료하고 저장 손실 가능성을 표시한다.
서버 자체가 강제 종료된 경우 마지막 정상 체크포인트까지만 복구한다.

기본 자동 시작은 **이 PC만 접속 가능한 Open 서버**이다. 사용 가능한 포트를 자동 할당하고,
상속된 네트워크 endpoint 설정을 사용하지 않는다. 방화벽 변경·포트 포워딩·UPnP·VPN을
수행하지 않는다. 다른 PC와 플레이할 때는 아래 LAN 설정 UI 또는 기존 전용 HTTPS 서버 구성을 사용한다.
초대/방 찾기/NAT 처리는 후속 작업이다.

패키지 CI는 실제 압축 해제 서버로 시작/중복 시작/데이터 잠금/독립 호스트/정상 종료/
재시작 캐릭터·실행 중 방 복원/클라이언트 dispose/실패·취소를 검사한다. Open Godot
검사는 화면과 동일한 시작·로그인·종료·재시작 메서드를 사용한다. 파일 선택/확인창의
수동 클릭, 실제 두 PC LAN/WAN, 클라이언트 OS 강제 종료 실측은 별도 인수 항목이다.


## LAN 호스트 설정 UI

1. 같은 빌드의 클라이언트와 서버 패키지를 준비하고 서버 실행 파일을 선택한다.
2. `LAN hosting (HTTPS)`를 켜고 `Local IPv4` 목록에서 사용할 이 PC의 IP를 입력한다.
   현재 IPv4만 지원하며 모든 인터페이스(`0.0.0.0`) 또는 다른 PC의 IP는 거부한다.
   포트는 기본 5443, 0이면 운영체제가 할당하며 실제 주소를 실행 후 표시한다.
3. `Choose server PFX`로 개인 키가 포함된 서버 인증서를 선택하고 암호를 입력한다.
   인증서 SAN에는 **선택한 IP 주소**가 있어야 하며 유효 기간과 서버 인증 용도를 검사한다.
   사설 CA로 발급했으면 `Choose public root CA`로 공개 루트 인증서를 선택한다.
   [TLS 발급/접속 안내](ONLINE_NETWORK.md)를 참고하며 OS 신뢰 저장소를 자동 변경하지 않는다.
4. `Start personal host` 후 표시된 HTTPS 주소와 CA SHA-256을 확인한다.
   `Copy connection invite`는 주소·Open 모드·CA 지문을 초대 JSON으로 복사한다. 게스트는 `Apply invite`로 적용한다. 게스트에게는 공개 CA만
   전달하고 PFX/개인 키/암호를 공유하지 않는다. 게스트는 Open 모드, 해당 주소, 공개 CA로
   `Check server` 후 계정 등록/로그인 → 캐릭터 → 같은 방에 참가한다.
5. 필요한 경우 해당 TCP 포트의 방화벽 허용을 직접 설정한다. 자동 포트 포워딩/UPnP/VPN은
   수행하지 않는다. 공유기 클라이언트 격리, DHCP 주소 변경, WAN 도달성은 별도 확인한다.

PFX 암호는 시작 시 입력란에서 지우고 서버 전용 stdin으로 한 번 전달한다. 명령행·환경변수·
호스트 DB·설정 파일에는 저장하지 않는다. 재시작할 때 다시 입력한다. LAN/루프백 호스트는
같은 Open 데이터 폴더를 사용하며 동시에 두 프로세스가 같은 데이터를 열 수 없다.
PFX 크기/설정 크기·주소·포트·인증서 SAN/기간/용도와 실제 HTTPS 체인 신뢰를 확인한다.
실패한 시작은 소유한 서버를 종료하며 HTTP나 인증서 검증 생략으로 재시도하지 않는다.
인증서 키는 .NET의 플랫폼 기본 임시 가져오기를 사용한다. Windows TLS 키 컨테이너와
macOS 임시 키체인 호환을 유지하고 Dispose에서 정리하며, 영구 키 저장을 요청하지 않는다.

자동 검사: 루프백과 조회 가능한 로컬 NIC 주소에 실제 HTTPS 서버를 바인딩하여 두 클라이언트
로그인·WSS 방 참가·서버 종료·재시작 복원을 검사한다. 잘못된 암호/CA/SAN/기간, 포트 충돌,
잘못된 IP/포트와 과대 시작 설정을 거부한다. Godot는 화면과 동일한 메서드로 LAN 설정·암호
비우기·로그인·종료를 검사한다. 이 자동 검사는 **동일 실행 머신의 프로세스 간 검사**이다.
물리 두 PC·공유기/방화벽·WAN·수동 파일 선택/클립보드 클릭·장시간 플레이는 미실행이다.
