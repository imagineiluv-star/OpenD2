# 공동 월드 코어·서버 — M5-01a/b

`WorldDefinition`의 `playerLimit`를 명시하면 최대 4명의 고정 플레이어가 미리 적재한
동일 월드에서 서로 다른 지역을 진행할 수 있다. 기본값은 1이며 기존 단일 플레이 월드의
콘텐츠/상태 해시와 저장 형식은 유지한다. 협동 설정은 콘텐츠 해시에 별도 표식을 넣는다.
다른 설정으로 저장을 열면 콘텐츠 불일치로 거부하며 원본 파일을 보존한다.

## 구현 범위

- 최대 8개 지역, 플레이어 4명, 기존 전체 배우/명령 예산을 유지한다. 각 지역은 설정한
  플레이어 정원만큼 전투 슬롯을 남겨 모두 같은 지역으로 모여도 상한을 넘지 않는다.
- 플레이어가 위치한 모든 지역의 이동·몬스터 AI·전투·회복/대기 시간을 진행한다.
  빈 지역은 정지한다. 죽은 플레이어도 지역을 점유한다. 부활·입장/퇴장 정책은 후속이다.
- 벽·근접 시야·길 찾기·아이템 줍기는 해당 배우의 지역 그리드를 사용한다. 다른 지역
  배우는 충돌/공격 대상이 아니다. 기존 길 찾기의 tick당 작업 예산은 월드 전체가 공유한다.
- 각 플레이어는 한 tick에 마지막으로 지정한 NPC/포털과 상호작용한다. 실행 순서는 배우 ID다.
  포털 도착 위치를 먼저 검사하며 동시 진입 시 먼저 도착한 살아 있는 몸체가 다음 진입을 막는다.
  실패는 위치·예약 입력을 보존한다. 성공은 이동한 플레이어의 옛 지역 입력만 취소하고,
  그 플레이어의 순번은 유지하면서 다음 tick 입력을 허용한다. 다른 플레이어의 예약은 유지한다.
- 퀘스트는 기존 처치/귀환 퀘스트 **하나를 공유**한다. 대화에 의한 단계 변경은 tick당 한 번이다.
  완료 보상은 살아 있는 참가자 모두의 체력을 한 번 회복하며 사망자를 부활시키지 않는다.
  개인별 수락/완료·보상 기록이나 원작 파티 퀘스트 규칙은 아직 구현하지 않았다.
- 체크포인트·파일 저장·복원·명령 재생은 모든 플레이어와 지역 상태를 보존한다.
  기존 `WorldPlayer`, `ActiveRegion`, `Collision`은 가장 낮은 플레이어 ID의 호환용 뷰다.
  다중 사용자 처리는 배우의 `Region`과 `World.GetRegion`을 사용해야 한다.
- 포털 입력 취소는 협동 세션 생성 시 할당한 최대 4,096개 명령의 재사용 배열을 쓴다.
  기존 큐 용량 안에서 보존 입력을 다시 넣으며 포털 전환 중 추가 배열을 만들지 않는다.

## 검증

`CooperativeWorldContracts`의 13개 계약은 서로 다른 원점/벽의 지역, 다지역 몬스터 전투,
원격 지역 전리품, 동시 포털 도착 충돌, 플레이어별 입력 취소/예산, 공유 보상 중복 방지,
콘텐츠 불일치 파일 보존, 저장/복원, 300 tick의 입력 순서 변경/재생,
정원/지역 예산과 준비된 포털 전환·일반 tick 무할당을 검사한다.

기존 단일 플레이 월드의 고정 상태 해시·지역 휴면·아이템·저장 변환 계약도 함께 실행한다.
3 OS CI는 전체 Core와 기존 온라인 Arena 계약/패키지 플레이를 실행한다. 합성 월드 검사는
실제 MPQ 지도 호환이나 두 PC 공동 월드 플레이 인수가 아니다.

## 서버 연결 — M5-01b

`cooperative-demo-v1`은 Camp/Field 두 지역, 왕복 포털, NPC와 처치 대상 두 마리를 가진
**내장 합성 콘텐츠**다. `CooperativeWorld.Create(1..4)`에서 서버가 배우 ID/시작 위치를
정하고 Core의 통행·몸체 충돌 검사를 거친다. 콘텐츠 hash는 월드 정의뿐 아니라 고정 seed,
4인 시작 배우/위치와 초기 아이템을 포함한다. 요청으로 파일 경로나 지도/배우 데이터를 받지 않는다.

| API/필드 | 계약 |
| --- | --- |
| `/health.roomWorld = 1` | 콘텐츠 확인·v5 월드 방 지원. 기존 Arena 기본 동작 유지 |
| 인증된 `GET /v1/worlds` | 허용된 `{ id, hash }` 목록 |
| `GET /v1/rooms?includeWorlds=true` | 월드 선택 정보를 포함한 목록. 기본 목록은 Arena만 반환 |
| 생성/참가 요청의 `world` | 목록과 정확히 같은 ID/hash 필수. 재로그인·재시작 후 기존 참가자도 다시 확인 |
| `RoomView.world` | 콘텐츠, 공유 퀘스트 진행, 수신자 배우의 `regionEpoch` |
| 월드 입력의 `region`, `regionEpoch` | 현재 배우 지역과 마지막 성공 포털 tick에 모두 일치해야 수락 |
| `opend2.room.v5` | 관심 범위·소비 순번·full/delta와 월드 상태. 월드 방은 v1~v4 업그레이드 거부 |

미지원/불일치 콘텐츠는 방·참가자·입력 순번을 변경하기 전에 거부한다. 계정/캐릭터 소유권,
비밀번호/초대, 호스트만 시작/닫기, 실행 중 고정 참가자와 재접속 규칙은 유지한다.
로그인 세션마다 생성 또는 참가에서 콘텐츠를 확인해야 해당 월드 방에 접근할 수 있다.
목록의 hash는 비밀이나 인증 수단이 아니며, 기존 인증을 대체하지 않는다.

포털 성공 시 이동한 배우의 이동 lease를 지우고 `regionEpoch`를 갱신한다. 같은 지역으로
돌아와도 예전 방문의 지연 입력은 거부한다. 잘못된 입력이 하나라도 있는 batch는 전체 거부하며,
소비 순번은 tick 실행/정지에 의한 폐기 뒤에만 갱신한다. 동료의 입력과 lease는 유지한다.
새 지역·방·연결·방문 epoch에서 관심 범위 이력을 초기화하고, 파티 배우는 다른 지역에서도
보내되 몬스터/바닥 아이템은 수신자 지역과 거리로 제한한다. 콘텐츠/퀘스트/자기 epoch가
변하면 full frame으로 기준 상태를 갱신한다. Arena 응답은 선택 필드를 생략한다.

월드 방을 포함한 저장은 DB version 3이며 콘텐츠 ID/hash, 정의 hash, 공유 퀘스트,
모든 배우/지역/아이템/입력과 참가자별 epoch를 보존한다. 실행 중 방뿐 아니라 로비의 콘텐츠도
읽을 때 검증한다. 불일치·잘못된 저장은 원본을 덮어쓰지 않는다. 재시작은 기존처럼 예약 입력과
잡고 있던 이동을 폐기하고 소비 순번을 정리한다. Arena DB v1/v2와 rules 7 변환은 유지한다.
월드 방의 승리는 공유 퀘스트 완료 후 닫을 때만 기록하며, 소지품 전달은 기존 방 종료 규칙을 쓴다.

`CooperativeRoomContracts`는 Realm/Open의 4인 참가·권한·콘텐츠 거부·NPC·왕복 포털·옛 방문
입력/원자 batch 거부·관심 범위·lease·재로그인·재시작·손상 저장 보존과 Arena 호환을 검사한다.
`CooperativeStreamContracts`는 실제 TLS 서버에서 두 .NET 클라이언트의 v5 전송, 공유 퀘스트,
분리된 지역 시야, 순번/epoch, full/delta와 재접속을 검사한다. 기존 3 OS 패키지 검증에도 포함한다.
