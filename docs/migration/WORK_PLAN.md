# 단계별 작업계획

전체 구현 상태: M0 기반 및 M1-01~06 기본 코드·합성 검증 구현. 실제 데이터 호환 인수, M1-05~06 형식 제한 및 M1-07은 남아 있다. 최신 증거는 [M1_06_RESULTS](M1_06_RESULTS.md)에 기록한다.

## 단계와 브랜치

| 단계 | 브랜치 제안 | 선행 조건 | 산출물과 종료 조건 |
|---|---|---|---|
| M0 기반 | `feat/m0-foundation` | 설계 커밋 확보 | 엔진 독립 솔루션, 도구 버전 고정, 깨끗한 환경의 빌드·내보내기 |
| M1 리소스 | `feat/m1-legacy-assets` | M0 | 인벤토리·핵심 파서·원본 지도와 캐릭터 뷰어 |
| M2 게임 수직 구현 | `feat/m2-playable-slice` | M1 | 마을·던전·전투·아이템·저장과 독립 실행 패키지 |
| M3 고품질 3D | `feat/m3-hd-presentation` | M2 | 동일 게임 상태의 원본/3D 표현, 품질·성능 인수 |
| M4 전체 콘텐츠 | `feat/m4-content-compatibility` | M2, M3 대표 검증 | 전체 콘텐츠·리소스 추적 및 회귀, 전체 게임 진행 검증 |
| M5 선택적 협동 | `feat/m5-coop-session` | M2 저장·판정 안정 | 권한 호스트·재접속·관심 영역 동기화 |
| M6 지역 스트리밍 | `feat/m6-world-streaming` | M3, M4 핵심 호환 | 연속 지역 이동·수명 관리·대형 월드 실측 |

M5는 오프라인 제품 출시의 필수 조건이 아니다. M6의 RegionId·상태 저장 경계는 M0/M2에 먼저 도입한다. M4 완료 전에 대표 콘텐츠로 스트리밍 연구는 가능하지만 전체 호환을 완료했다고 표시하지 않는다.

각 단계는 필요하면 아래 작업 ID별 작은 브랜치/PR로 나눈다. 선행 단계가 병합된 기준에서 다음 브랜치를 만든다. 미리 모든 브랜치를 생성하지 않는다. 기능과 무관한 이름 변경·공통 프레임워크 도입은 묶지 않는다.

## 실행 백로그

### M0 — 기반 구현과 인수

- [x] **M0-01** Godot .NET / .NET SDK / export template 조합 선정. Windows x64와 macOS arm64 빈 앱 내보내기. 결과와 버전 고정. 막히는 조합은 채택하지 않는다.
- [x] **M0-02** Core / Assets / Client / AssetAudit / Tests 생성. Godot 없이 Core·Assets 빌드되는 참조 구조 검증.
- [x] **M0-03** CI에 코어 빌드·테스트·엔진 의존성 검사·클라이언트 export 연결. 게임 데이터 없이 수행 가능한 synthetic fixture만 사용.
- [x] **M0-04** 의존성 출처·라이선스·소스 빌드 목록과 ignore 규칙 작성. 사용자 데이터 및 추출 캐시가 커밋되지 않게 검사.
- [ ] **M0-05** 설정/세이브/캐시 경로, 구조화 로그, 프레임·tick·메모리 측정 기반 구현. 기본 오프라인 동작 검증.

M0-03은 3개 OS CI 성공으로 검증했다. M0-05의 frame p95·관리 힙·로그는 구현했고, 실제 게임 tick 계측은 M2 시뮬레이션 구현 시 연결한다. macOS는 공식 universal template로 arm64를 포함해 내보낸다.

M0 완료 시 실제 실행 가능한 최소 Godot 앱이 있어야 한다. 빈 DLL과 미사용 추상화만으로 완료 처리하지 않는다.

## 작업 완료 기록 양식

각 구현 PR에는 `작업 ID / 변경 이유 / 실제 구현 / 검증 명령과 결과 / 미검증 환경 / 남은 항목`을 기록한다. 코드 리뷰와 관련 검증 후만 체크박스를 완료로 바꾼다. 리소스가 없어 실행하지 못한 시험은 통과로 표시하지 않는다.

## 현재 장애 요인

1. 개발 저장소: `imagineiluv-star/OpenD2` 포크 생성 및 쓰기 권한 확인. `docs/csharp-godot-migration-plan-20261007` 브랜치에서 설계 관리. 원본 `eezstreet/OpenD2`에는 직접 쓰지 않는다.
2. 원본 게임 데이터 없음: 파서 synthetic fixture와 코드 작업은 가능하나 전체 호환 인수는 실제 파일 필요.
3. 목표 최소 사양 미확정: VALIDATION의 잠정 예산으로 계측을 시작하고 M3 대표 장면에서 확정.
4. 신규 3D 아트 미제작: 코드 마이그레이션과 별도 콘텐츠 제작 작업으로 추적.
