# M2-06d — 시작 메뉴와 이어하기

기준 master `19d491f`, 브랜치 `feat/m2-06d-start-menu`.

## 구현

- 일반 시작은 Simulation 탭의 메뉴에서 대기한다. New game을 선택하기 전에는 tick·전투·이동이 진행하지 않는다. 첫 시작의 Continue는 비활성화한다.
- Menu (Esc)/Esc로 메뉴를 열면 현재 세션을 일시정지하고 이동 경로·입력과 NPC 대기 응답을 정리한다. 플레이 컨트롤은 숨기며 명령 제출도 차단한다. 왼쪽 표시/음량/데이터 설정은 계속 접근할 수 있다.
- Continue current session은 메모리의 진행을 보존한다. 메뉴 전에 Pause였다면 Return to paused session으로 돌아가 Pause를 유지한다. 메뉴에서 머문 시간을 tick에 누적하지 않는다.
- New game은 현재 장면/Seed로 다시 시작한다. 진행 중에는 확인을 요구하고 취소 시 메뉴와 현재 진행을 유지한다. 체크포인트 파일은 변경하지 않는다.
- Load checkpoint는 현재 장면의 파일 또는 백업이 있을 때 활성화한다. 파일 존재는 호환성 통과를 의미하지 않는다. 기존 GameSave의 버전·콘텐츠·checksum 검사를 거쳐 읽으며, I/O 중에는 메뉴의 세 버튼과 Esc 전환을 막는다.
- 성공/백업 복구 후에도 메뉴에 머물러 결과를 표시한다. Continue를 선택해야 게임을 진행한다. 실패하면 기존 세션·파일을 유지하고 오류를 표시한다. 플레이 화면의 Load checkpoint에도 진행 교체 확인을 적용했다.
- 체크포인트 작업을 await 가능한 성공/실패 결과로 연결했다. 경로와 월드 정의를 작업 시작에 고정하고, 로드 시 이전 아이템 선택을 해제한다. 서버·네트워크 요청이나 새로운 저장 형식은 없다.

## 검증

`OPEND2_M206_MENU_READY`를 개발 실행과 export/압축 해제 배포 검사에 필수로 추가했다. 합성 장면과 임시 저장 폴더에서 실제 메뉴/비동기 GameSave 경로를 검사한다.

- 시작 메뉴에서 3초 프레임 처리 후 tick 0 유지.
- 이동 중 메뉴 열기, 명령 차단, 상태 hash 유지, 재개 후 중립 이동과 1 tick만 진행.
- 기존 Pause 상태 복원, 새 게임 확인 취소 시 진행 유지.
- 비동기 불러오기 중 메뉴 버튼/재개 차단, 저장 상태 hash 복원과 메뉴 대기.
- 손상된 체크포인트 실패 시 현재 hash 유지, 유효 백업 복구 후 대기.
- 확인한 새 게임은 tick 0으로 초기화하고 기존 체크포인트/백업을 보존.

로컬 빌드 경고/오류 0, 계약 **268/268**, Python 패키징/다운로드 **16/16**, 상태 벡터·엔진 경계, Godot import/시작, Linux self-contained export와 SDK 검색 경로를 제거한 배포 실행 검사를 통과했다. 원격 3개 OS 결과와 압축 해제 검사는 PR에 기록한다. 원본 파일·실제 GUI 입력·청취 검증을 헤드리스 marker로 대체하지 않는다.

초기 메뉴 검사는 부모 탭의 표시 상태가 확정되기 전 `_Ready`에서 실행해 재개 tick 검사가 실패했다. 앱 초기화 완료 뒤 deferred 호출로 실제 프레임 처리 순서에 맞췄고 전체 검증을 다시 통과했다. 네이티브 런타임 빌드 중의 사전 검사는 실행 파일 누락으로 실패했으며, 최종 검사는 소스 빌드한 런타임을 포함한다.

## 인수와 남은 범위

QA-01/04/06/08/09의 메뉴 진입·재실행·저장 흐름을 갱신했다. 실제 창에서 Esc/키보드 포커스·확인창·창 크기·스크롤과 읽기 어려운 경로/오류 문구를 확인해야 한다. 이 환경의 GUI/원본 MPQ 플레이 인수는 **NOT_RUN**이다.

현재 장면별 단일 체크포인트만 지원한다. 원본 장면은 New game 후 기존 Load legacy scene JSON/Load remembered scene으로 명시적으로 선택하고 해당 장면의 체크포인트를 불러온다. 기억 경로 자동 로드·여러 캐릭터/저장 슬롯·캐릭터 생성/선택·스킬 UI는 후속 범위다. 원본 게임 규칙과 D2R급 그래픽이 구현된 상태는 아니다.

기존 `v0.2.0-rc.2`에는 오디오·가방/장비 패널·이번 메뉴 변경이 포함되지 않는다. GUI 인수에는 후속 master 기반 배포본이 필요하다.
