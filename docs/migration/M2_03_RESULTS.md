# M2-03 마을·던전·지역 이동·NPC 퀘스트 검증

검증일: 2026-10-08 UTC. 저장소: `imagineiluv-star/OpenD2` 독립 저장소. 작업 브랜치: `feat/m2-playable-slice`, 기준 master: `4a34499742c0fd67513dadbe3d156e1d7023f032`. M2-02의 기존 파일·리소스 로더·전투 코드를 이어서 구현한다.

## 변경 이유와 실제 구현

이전 합성 전투장은 한 지역 안에서만 동작했다. 이번에는 한 마을과 던전을 연결하고 NPC에게 퀘스트를 받아 처치 후 돌아오는 흐름을 구현했다. 지역을 떠났다가 다시 들어갈 때 체력·위치·몬스터 사망·진행 상황이 초기화되지 않도록 판정을 Core에서 관리한다.

| 구성 | 책임 |
|---|---|
| `WorldDefinition` | 불변 지역 지도·포털·NPC·처치 대상·콘텐츠 해시와 입력 상한 검사 |
| `GameWorld` / `GameSimulation` | 활성 지역, 이동 전 검증, 비활성 객체 보존, 퀘스트·1회 보상, 입력/이벤트/재생 |
| `SimulationPreview` | Camp/Cellar 표시, NPC/포털 표식, E 상호작용, 퀘스트 상태·목표 수 표시 |
| `WorldContracts` / `eng/validate.py` | 지역·NPC·퀘스트·실패 경계·할당 검사, Godot 전체 흐름 시작 검사 |

게임 규칙은 클라이언트의 화면 노드가 결정하지 않는다. Godot가 Core에 입력을 보내며 Core가 결과를 판정한다. 신규 외부 라이브러리·DLL 바이너리·서버 프로세스·게임 MPQ는 추가하지 않았다.

## 플레이 흐름

1. **Simulation** 탭에서 지도를 클릭한다. 방향키로 이동하고 초록색 **Camp Guide** 근처에서 **E / Interact**로 `Clear the cellar`를 수락한다.
2. 금색 **Cellar** 포털 근처에서 E를 눌러 던전으로 이동한다.
3. **Space / Attack nearest**로 세 몬스터를 처치한다. 회색 벽과 보라색 미확인 지형은 이동을 막는다. 벽의 통로를 통해 다른 방으로 이동할 수 있다.
4. 던전 입구 **Camp** 포털에서 E로 돌아온 뒤 Guide에게 다시 E로 보고한다. 완료 시 체력을 한 번 회복한다.
5. 공격과 상호작용을 같은 tick에 실행하면 상호작용이 실패할 수 있다. Space를 놓고 E를 누른다. E는 누르는 순간 1회 처리한다. **Verify replay**는 지역 이동과 퀘스트를 포함해 같은 기록을 재생한다.

모든 상태는 현재 프로세스 안에서만 유지된다. **New run**과 앱 종료는 진행을 초기화한다. 파일 세이브는 M2-05이며, 이번 결과를 저장/복원 완료로 표시하지 않는다.

## 상태·실패 처리와 예산

- 세션은 플레이어 1명, 현재 지역 1개를 진행한다. 비활성 지역의 AI·전투·이동·쿨다운·피격 정지는 정지하고 위치·체력·사망·AI 모드/대상을 보존한다. 재방문은 해당 값에서 이어진다. 시체는 재생성하지 않는다.
- 포털은 출발 지역·근접 거리·시야를 검사한다. 같은 tick에 성공한 공격·피격·사망은 사용을 막는다. 도착 지점의 정적 충돌과 생존 몸체 겹침을 확인한 뒤 지역·위치를 함께 갱신한다.
- 도착 지점이 막히면 출발 지역·위치의 전환과 예약 입력 취소를 수행하지 않는다. 그 tick에 이미 수행한 정상 이동/전투/타이머까지 되돌리는 기능은 아니다. 현재는 사전 로드 지도이므로 비동기 파일 읽기·저장 실패 복구는 후속 범위다.
- 성공한 전환은 이동 의도와 남은 예약 명령을 지운다. 이전 지역 명령이 재방문 뒤 되살아나지 않는다. sequence 최댓값은 유지하며 제출 tick 경계만 전환 시점으로 맞춰 새 지역의 즉시 입력을 허용한다. 도착 지역은 다음 tick부터 진행한다.
- NPC/포털은 비전투 표식으로 몸체나 체력이 없다. 상호작용 거리·시야는 Core가 확인한다. 한 tick에 여러 `Interact`가 승인돼도 마지막 대상에 한 번만 적용한다.
- 퀘스트는 `Available → Active → ReadyToTurnIn → Completed`. 목표를 먼저 처치하고 수락해도 완료 가능하다. 무관한 몬스터는 진행도에 포함하지 않는다. 완료 보상 회복은 한 번뿐이며 이후 피해를 입고 재대화해도 다시 회복되지 않는다.
- 최대 8지역, 합계 1,048,576셀, 32포털, 32목표다. 각 지역은 몬스터 127개와 방문 플레이어 1명의 자리를 갖는다. 최대 1,017개 전투 객체가 메모리에 존재한다. 기존 자유 이동/한 지역 API도 유지한다.
- Core `Step`은 활성 객체만 갱신하지만 AI/몸체 검사에서는 전체 유한 배열을 순회한다. 최대 활성 128개 × 전체 1,017개 규모로 제한되며 대형 월드의 공간 인덱스·스트리밍 성능을 보장하지 않는다. 이벤트 공간은 `6 × 전체 객체 수 + 128 + 4`다.

## 서버 구성

현재 배포는 `OpenD2.Client`가 사용자 PC에서 `OpenD2.Core`를 실행하는 오프라인 방식이다. 중앙 게임 서버·로그인·DB 설치가 필요 없다. 이는 UI만 있고 게임 판정이 없는 구조가 아니라, 엔진과 독립된 판정 라이브러리를 같은 프로세스에서 실행하는 구조다.

M5에서는 방장 PC 또는 별도의 `OpenD2.Server` .NET 호스트가 같은 규칙을 실행하고 참가자의 입력 소유권·빈도·범위·순번을 검증한다. 전용 서버에는 Godot 화면/GPU가 필요하지 않다. 별도 서버 프로젝트와 네트워크 프로토콜은 아직 구현 전이다. 현재 1인 월드는 다중 플레이어별 지역·퀘스트, 활성 지역 집합과 재접속 모델로 확장해야 한다. 호스트와 중계 서비스에는 연산/통신 비용이 생긴다. 상세는 [ADR-002](ARCHITECTURE.md#adr-002-로컬-우선-선택적-협동-세션)에 기록한다.

## 규칙 버전과 검증

`RulesVersion = 3`. v2 상태 뒤에 world 유무와 콘텐츠 hash·플레이어·활성 지역·퀘스트 상태가 추가됐다. 콘텐츠 hash는 모든 지역 지도·포털·NPC·목표를 포함하고 생성 시 한 번 계산한다. 진단 상태 hash는 모든 활성/비활성 객체·난수·입력 경계·예약 명령을 포함한다. snapshot은 소유 사본이며 진행 중 snapshot을 불러오는 API는 아직 없다.

별도 Python `struct.pack` little-endian 계산으로 만든 기준값:

| fixture | SHA-256 |
|---|---|
| 기존 이동/입력의 v3 인코딩 | `82f67fd7b884cc2046bc99a27c16af3749e6f4086959a045700c4786604f998f` |
| 기존 1 HP 몬스터 처치의 v3 인코딩 | `6805dac771b7e06d3d2003c6439c54e64a17de15ca4e63bbe22bcb6e650f2819` |
| 테스트 Town/Dungeon 콘텐츠 | `85e4863a4455df1930320c2618a7fba6b2271f61dbcd1b8a81d640086a4e0f3b` |
| tick 5 퀘스트 완료·마을 복귀 | `a42bbb7993e65ccf5f0aef9587ac8ceb18ea5030a981ad94d7f8f9dcada77856` |

로컬 Linux, .NET SDK 10.0.401 / Godot 4.6.3 .NET / 기존 고정 native backend에서 수행했다.

```sh
dotnet run --project tests/OpenD2.Tests -c Release
python eng/validate.py --export Linux
env -u DOTNET_ROOT -u DOTNET_ROOT_X64 PATH=/usr/bin:/bin \
  ./artifacts/Linux/OpenD2.x86_64 --headless --quit-after 120 -- --smoke-test
python eng/verify.py
git diff --check
```

- 전체 Debug 솔루션 빌드: **경고 0, 오류 0**. Debug와 최종 Release 계약 **147/147 통과**(기존 125개 + 지역/퀘스트 22개). 최종 world golden·다중 목표 검사는 Release에 추가 확인하고 원격 CI에서도 실행한다.
- 잘못된 콘텐츠·예산·전역 ID·플레이어 수·타 지역 입력, NPC 거리/벽, 피격/공격/사망 중 전환, 막힌 도착점, 이전 명령 취소·sequence 유지, 지역 동결/재방문, 수락 전 처치·중복 보상·무관한 처치·여러 목표를 검사한다.
- 200tick에서 정렬 전 엔티티 순서 및 40ms 대 13+27ms 프레임 분할에 관계없이 지역/퀘스트 이벤트와 최종 hash가 같고 입력 재생과 일치했다. 전환 전에 미리 예약했다가 취소된 명령도 재현한다.
- 8개 지역·1,017개 객체에서 warmup 100tick 뒤 1,000tick의 관리 메모리 할당 **0바이트**. 비활성 7개 지역의 값 전체가 유지되고 현재 지역에서는 실제 전투가 진행됐다. 화면·진단 hash·snapshot까지 무할당이라는 뜻은 아니다.
- Godot import·헤드리스 시작·Linux self-contained export 성공. `OPEND2_M203_WORLD_READY`는 수락 → 던전 진입 → 처치 → 귀환 → 완료·1회 회복과 재생 일치를 검사한다. SDK 환경을 제거한 배포 파일도 종료 코드 0으로 모든 준비 마커를 출력했다.
- 엔진 참조 경계·신규 트리 소스 전용 검사와 diff 공백 검사를 수행한다. 원본 게임 자료·세이브·추출 캐시와 기존 C++ 파일은 변경하지 않는다.

### 원격 CI

기능 브랜치에 반영한 후 Windows x64·Linux x64·macOS universal 결과를 확인하고 실행 링크를 기록한다. 로컬 Linux 결과를 다른 OS의 실행 성공으로 간주하지 않는다.
